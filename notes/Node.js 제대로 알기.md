## Node.js 란?
- 자바스크립트라는 언어를 알아듣는 프로그램
- 어떤 컴퓨터에 Node.js를 설치한다는 건, 해당 컴퓨터가 할 줄 아는 언어들의 목록에 자바스크립트를 추가한다는 의미

		- 이 두 함수는 각각 파일 url을 경로로, 파일 경로를 파일 url로 바꿔줌

		- 파일 경로는 운영 체제에서 파일이나 디렉토리의 위치를 나타내는 문자열

## call stack
- 함수를 사용할 때마다 그와 관련된 정보들이 쌓이는 곳
- LIFO 형식
- 한계치 이상으로 함수가 연이어 호출되면 stack overflow
- call stack을 통해 오류가 발생한 지점을 알려주는 것을 stack trace
## 이벤트 루프
- 자바스크립트 코드가 실행되면서 동기/ 비동기 작업이 실행됨
- 코드가 실행되면 v8엔진에 의해 파싱되고, 동기 작업은 즉시 처리되며, 비동기 작업은 하위 계층으로 전달됨
- 동기적인 작업은 call stack에서 바로 실행됨
- 스택이 비워질 때까지, 대기가 모두 없어질 때까지 기다린 후 비동기 작업이 처리됨
- 파일관련 작업, http요청, 타이머 등의 비동기 작업들을 libuv로 넘김
- libuv는 node.js가 운영체제와 소통해서 빠르게 일을 처리하게 도와주는 도구
	- node.js가 컴퓨터에서 동작하려면 해당 컴퓨터가 사용하는 운영체제와 소통할 수있어야 함
	- libuv는 그 중간 다리의 역할을 맡아서 파일 열기나 네트워크 요청 등을 운영체제에 요청한 다음 그 결과를 다시 node.js에 전달하는 것
	- 따라서 libuv는 어떤 운영체제에 요청하는 지에 따라서 하는 일의 차이가 있음
	- libuv에 의해 비동기 작업들이 백그라운드에서 처리됨
- libuv에 속한 Thread Pool이란 여러 주방장이 주방장이 손님들의 주문을 동시에 처리하는 곳이라고 생각하면 됨 
	- 여기서 멀티 쓰레딩으로 비동기 작업들이 처리됨
- libuv에 속한 이벤트 루프는 손님들과 주방 사이를 오가는 직원과 같다고 생각하면 됨
	- 손님이 요리를 주문하면 대기표를 건내준 다음 주방에 주문을 전달하고, 수시로 주방을 확인하여 요리가 나오는대로 손님을 호출해주는 일을 맡음
	- 프로그램이 실행을 시작하며 이벤트 루프가 초기화 됨
	- 자바스크립트 코드가 처음 실행되면서 콜 스택에 쌓인 동기 코드가 처리되기 시작함
	- 동기 코드가 끝나면 비동기 작업의 결과나 대기 중인 콜백을 처리하기 위해 이벤트 루프로 넘어감
	- microtask 단계에서는 promise의 then 메소드와 process의 nextTick 함수와 같은 마이크로 태스크가 처리됨
		- 높은 우선순위를 가진 일을 처리하는 단계
	- timers Phase부터의 작업들을 이벤트루프는 쉬지 않고 처리
		- 여기서는 setTimeout이나 setInterval로 설정된 타이머가 만료되었을 때 해당 콜백을 실행
	- pending phase는 드물게 실행되는 단계로 여러 이유에 의해 이전 사이클에서 처리되지 못한 작업들이 마저 처리됨
	- poll phase는 가장 중요한 단계 중 하나로 파일 읽기, 네트워크 응답 등 비동기 작업의 완료를 기다리고 완료된 작업의 콜백을 실행함
	- check phase는 setImmediate 콜백을 실행하여 한 사이클을 마무리 한 뒤 다시 timer phase로 돌아감
	- 이벤트 루프는 마이크로 태스크와 각 페이즈를 체크하며 더 이상 처리할 작업이 없으면 종료됨
## 예제 코드 실행 과정
- 먼저 동기코드인 콘솔로그가 콜 스택에 담기게 됨
	- 다른 함수를 호출하는 코드가 아니므로 콜 스택에 들어가자마자 빠져나오면서 실행됨
	- 터미널에 가장 먼저 결과가 출력되고 콜 스택에서는 해당 코드가 사라짐
- 다음으로 process.nextTick() => 
	- 이 함수는 동기 코드들이 모두 실행된 직후 실행할 작업을 등록함
	- 콜 스택에 먼저 등록됨
	- 먼저 실행했던 콘솔로그와 마찬가지로 실행되면서 콜 스택에서 빠져나옴
	- 그리고 해당 메소드로 등록한 콜백이 메모리와 태스크 큐에 들어감
		- 메모리는 콜백 함수 자체가 저장되는 공간이고 태스크 큐는 이를 실행할 때를 스케쥴링 하기위한 대기열
	- 그 다음 promise의 then 메소드
		- 이 메소드 역시 콜스택에 올려졌다가 바로 실행되어 빠져나감
		- 해당 메소드에 인자로 전달한 콜백 함수가 역시 태스크 큐와 메모리로 들어감
			- then( ( ) => ) 여기서 ( ) => 이 부분이 태스크 큐로
	- nextTick과 then은 태스크 큐 내에서 다른 공간에 할당됨. 마이크로 태스크로 구분됨
	- 다음은 setTimeout 메소드
		- setTimeout의 콜백은 매크로태스크 큐에 속하는 타이머 큐로 들어감
		- 매크로태스크 큐는 마이크로태스크 큐보다 우선순위가 낮으므로 앞서 등록한 두 콜백보다 늦게 실행됨
	- 다음으로 setImmediate 메소드
		- checkPhase에서 실행할 콜백함수를 전달
		- 인자로 전달한 콜백함수는 체크 큐에 들어감
	- 다음은 파일로부터 비동기적으로 데이터를 읽어오는 readFile함수
		- 콜백함수는 매크로태스크 큐인 i/o 큐로 등록됨
	- 다음은 동기 코드인 콘솔로그
		- 동기코드이기 때문에 바로 터미널에 결과 출력
	- 이렇게 모든 동기코드가 처리된 후 태스크 큐에서 대기 중인 작업들이 우선순위에 따라 처리됨
		- 프로미스의 then 함수 실행되어 터미널에 겨로가
		- 그 다음은 nextTick 함수 처리
		- 매크로 태스크에 속하는 큐들이 차례로 처리
		- 마지막으로 setTimeout

	- 정보를 받아오기 전에 해당 정보를 캐시에 업데이트 하는 일도 수행함
	- 해당 작업이 동기적으로 이뤄진다면 캐시 저장에 걸리는 시간만큼 사용자 정보의 반환도 늦어질 것
	- 이를 해결하기 위해 사용
	- 정보를 받아오는 작업을 nextTick으로 넘겨주면 이는 동기 코드들이 모두 실행된 다음 비동기적으로 진행됨
	- nextTick은 프로미스와 더불어 비동기 작업들 중 가장 최우선 순위를 갖는 microtask에 해당함
		- 따라서 어떤 작업이 중요한 다른 작업의 진행은 방해하지 않도록 비동기 작업으로 넘기되, 비동기 작업 중에서는 가장 먼저 처리되도록 하고싶을 때 사용
## EventEmitter
- node.js의 내장 모듈로 이벤트 기반 프로그래밍을 위한 클래스
- 일종의 알림 시스템으로 프로그램 안에서 무언가 중요한 일이 일어났을 때, 그걸 다른 부분에 알려주는 역할을 함
- import { EventEmitter } from 'events';
- const emitter = new EventEmitter( );처럼 해당 클래스의 emitter 인스턴스를 만들어서 사용
- emitter.on( ) 메서드
	- 첫 번째 인자로 주어진 문자열을 이름으로 갖는 이벤트를 등록함
	- 그 이름의 이벤트를 발생시킬 때마다 두 번째 인자로 전달된 리스너 함수를 실행
- emitter.once( ) 메서드
	- 이벤트의 이름과 해당 이벤트 발생 시 호출할 리스너 함수를 인자로 받음
	- on 메서드와의 차이점은 딱 한번만 실행한다는 것
- emitter.emit( 이벤트 이름 )
	- 해당 이벤트에 할당한 함수들이 호출되어 결과 출력
	- 이벤트들이 실행되고 나면 한 번만 실행되는 once는 없어짐
## child_process와 cluster모듈
- child_process
	- node.js에서 별도의 프로세스를 생성하여 실행할 수 있도록 도와주는 모듈
	- 현재의 프로그램 내에서 다른 프로그램이나 시스템 명령어를 실행할 수 있도록 해주는 것
	- exec
		- 시스템 명령어를 실행하고 결과를 받아올 수 있는 함수
		- 명령어 전체의 문자열을 첫 번째 인자로 넘겨줌
	- execFile
		- 셸을 거치지 않고 직접 명령을 실행
		- 즉 bash, zsh, powerShell, cmd 등으로 하여금 명령어를 전달하게 하는 것이 아니라 운영체제에게 직접 말함
		- 실행 파일을 첫 번째 인자로, 옵선들은 두 번째 인자인 배열에 넣어 전달
		- 빠르고 보안성이 높음
		- 사용자 입력을 직접 셸에 전달하지 않기 때문에 셸 인젝션 등의 위험으로부터도 자유로움
	- spawn
		- 새로운 프로세스를 생성하여 스트림 방식으로 실시간 데이터를 처리할 수 있음
		- const process = spawn('node', [ ' - v ' 
			- spawn 함수를 호출해 새로운 프로세스 생성
			- process 상수에 할당될 반환값은 childProcess의 인스턴스
			- process.stdout.on()
				- .stdout은 생성된 프로세스의 표준 출력 스트림
				- 여기에 on 메서드를 사용해서 스트림에서 데이터가 발생할 때마다 호출되는 이벤트 리스너를 등록할 수 있음
				- data는 스트림으로부터 출력되는 데이터로 buffer 객체로 반환되지만 암묵적으로 문자열로 반환됨
			- process.stderr.on()
				- 표준 에러 출력 스트림
				- 오류가 발생하면 이 스트림에서 오류 메세지를 담은 data가 출력될 것
	- fork
		- 오직 자바스크립트 모듈을 실행하는 데 특화되어 있음
		- 즉 spawn이 node.js 전용으로 특화된 버전
		- const child = fork('./문서.js)
			- fork를 사용하여 자식 프로세스를 생성
			- child 상수에는 childProcess 객체가 저장됨
			- 
- import { exec } from 'child_process
	- exec( )
	- 이 함수의 첫 번째 인자로는 시스템에서 실행할 명령어를 문자열로 넣어줌
	- 두 번째 인자로는 (error, stdout, stderr ) 이 세 매개 변수를 갖는 콜백함수를 전달함
		- 각각 오류정보, 명령어의 실행 결과, 명령어 실행 중 표준 에러 출력
## worker_threads
- 여러 스레드를 활용하기 위한 모듈
- child_process를 통해 구현한 멀티프로세싱은 식당을 여럿 차려서 운영하는 것과 같음
	- 여러 개의 독립적인 프로그램이 자기만의 메뫃리 공간을 갖고 따로따로 돌아가는 것
- 반면 멀티스레딩은 한 식당안에 요리사가 여럿 있는 것과 같음
	- 하나의 프로그램 안에서 여러 작업들이 함께 진행되는 것
	- 요리사들이 주방과 식재료를 함께 사용하듯, 스레드들은 메모리 공간을 공유한다는 차이가 있음
- 자바스크립트에서는 비동기 작업이 알아서 멀티스레딩으로 처리되기 때문에 대부분ㄴ의 상황에서는 개발자가 직접 멀티스레딩을 프로그래밍할 필요가 없음
- 하지만 단순히 시간만 오래 걸리는 일이 아닌, cpu에 부담을 줄 수 있는 작업들은 직접 다른 스레드를 만들어 실행해야 메인 스레드가 느려지거나 멈추는 일을 막을 수 있음
	- 이미지 편집, 대용량 데이터 압축, 0에서부터 큰 수까지 더해나가는 것과 같은 무거운 작업 들

- 분리된 스레드에서 처리할 작업을 worker문서에 작성
- index문서는 프로그램이 실행될 메인 스레드가 될 것
- index 문서
	- import { worker } from 'worker_threads'
	- const worker = new Worker( './worker.js , { } );
		-  생성자의 첫 인자로는 실행할 워커 스크립트의 경로 전달
		- 두 번째 인자는 데이터
	- worker.on('message', (message) => {})
		- 워커 스레드에서 넘긴 메세지가 출력됨
	- worker.on('error', (error) => {]})
	- worker.on('exit', (code) => { })

- worker 문서 
	- import { parentPort, workerData } from 'worker_threads'
		- parentPort는 메인 스레드와 통신할 수 있는 창구
		- workerData는 위 index문서 worker 생성자에서 실어보낸 데이터
	- function heavyCalc( num ){ }
		- const result = heavyCalc(workData);
		- 0부터 해당 숫자까지 더해나가는 무거운 작업이 워커 스레드에서 실행된 뒤 result 상수에 저장됨
	- parentPort.postMessage(result);
		- result를 parentPort.postMessage(result) 인자로 전달하면 메인 쪽에서(index문서)에서 워커의 message 이벤트를 통해 전달됨
	- parentPort.close();
## package.json
- 프로젝트에 대한 정보를 담고 있으며 프로젝트의 설명서 같은 역할을 함
- npm을 비롯한 패키지 관리 도구들은 이 파일을 보고 프로젝트를 어떻게 관리할지 결정함
- node.js의 실무 프로젝트에서는 대부분 최상위 폴더에 이 package.json 문서가 포함되어 있음
- 이 문서는 직접 작성될 수도 있지만, 실무에서는 npm또는 프레임 워크의 CLI등을 통해 생성됨
- SemVer
	- 소프트웨어 버전을 체계적으로 관리하기 위한 규칙
	- 예를 들어 4.17.1
		- 마지막 숫자는 작은 개선이나 버그 수정이 있을 때 올라감 -> 기능 추가 없이 안정성만 높아짐
		- 가운데 자리는 기능은 추가되었지만 기존의 코드와 호환될 때 올라감
		- 맨 앞자리는 큰 변화가 있을 때 올라감
			- 이전 버전과 호환되지 않는 개선이 있을 때 등
	- 메이저 버전(맨 앞자리) 앞에 캐럿( ^ )을 붙이면 메이저 버전은 고정하고 마이너와 패치 업데이트를 허용한다는 의미가 됨
	- 캐럿이 아닌 물결을 붙이면 메이저와 마이너(중간자리) 버전은 고정하고 패치 업데이트만 허용
	- * 는 가장 최신 버전을 사용하겠다는 의미
	- OR 연산자나 부등호로 버전을 표현할 수도 있음
## npm
- node.js에서 기본으로 제공되는 패키지 매니저
- 패키지 매니저란 스마트폰의 앱스토어처럼 다른 사람들이 만든 코드를 내 프로젝트에 다운받아서 쓸 수 있게 해주는 프로그램
- 뿐만아니라 프로젝트에 필요한 패키지의 버전을 관리하고, 스크립트를 실행하며, 개발 환경을 간편하게 설정할 수 있게 도와줌
- npm -v 버전 출력
- npm init
	- 직접 새로운 프로젝트 생성할 때, 해당 프로젝트의 최상위 폴더에서 실행
	- 프로젝트를 생성하기 위한 질문들이 뜨고 입력
	- npm init -y는 모든 질문에 yes라고 답하고 빨리 package.json 파일을 만들어 달라는 의미
