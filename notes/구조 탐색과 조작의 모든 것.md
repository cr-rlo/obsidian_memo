## HTML만으로는 부족했던 이유
- 구조만 있고, 조작은 없던 시절
- 정적 HTML 문서
- HTML문서는 마치 종이로 인쇄된 책처럼, 그저 읽는 것만 가능한 정적 콘텐츠
- 단순성, 빠른 로딩, 접근성이 좋다는 장점
- 상호작용석 부족, 참여도 감소, 업데이트가 어렵다는 단점
- 이 단점들을 수용하는 과정에서 자바스크립트 등장
- 자바스크립트는 직접 HTML 자체를 변경하여 조작할 수는 없으나 DOM을 조작하여 브라우저의 메모리 내 표현을 변경함
	- 브라우저가 HTML 문서를 읽어들인 후, 내부 메모리 상의 객체 기반 구조로 바꿔 저장한 데이터를 조작하게 됨
	- 이 객체 기반 구조가 바로 Document Object Model, 즉 돔
- DOM이란 다큐먼트 문서를 오브젝트 객체로 모델링한 구조
	- 텍스트로 작성된 HTML 문서를 브라우저가 읽고 각 요소들을 하나하나 객체화하여 트리구조로 메모리에 구성해 놓은 것
	- 정적인 마크업을 동적으로 조작 가능하게 만드는 중간다리 역할을 DOM이 함
- DOM 구조 피라미드
	- DOM은 HTML 문서를 트리 형태의 객체 구조로 바꾼 것으로 자바스크립트가 브라우저와 상호작용할 수 있는 창구
	- DOM은 우리가 작성한 HTML을 하나의 거대한 객체 트리로 변환해줌
	- DOM 트리의 각 노드는 HTML 요소를 나타내며 자바스크립트는 이 노드를 찾아서 웹페이지를 조작
- HTML 중첩 구조
	- HTML은 단순한 텍스트 문서처럼 보이지만 실제로는 중첩, 트리(nesting) 구조를 갖는 계층적 언어
	- 중첩은 부모 자식간의 관계로 작동
	- 들여쓰기와 같은 중첩 구조는 곧바로 트리 구조로 해석될 수 있음
	- 어떤 태그가 무엇의 안에 포함되어 있는지를 정확히 파악한 후, 각 태그를 부모, 자식, 노드로 구성된 객체 트리로 변환하는 것
- HTML은 문서 구조의 설계도 
- 자바스크립트는 이 구조를 조작하는 기능 담당자
- 이 둘 사이를 연결해주는 매개체가 DOM
## DOM은 무엇인가
- 돔은 브라우저가 HTML을 이해하기 위해 만들어낸 구조화된 결과이자, 자바스크립트가 브라우저와 소통할 수 있도록 해주는 공식적인 인터페이스(API)
- 브라우저는 HTML 파서라는 프로그램을 통해 이 텍스트를 한 줄씩 읽으며 의미 단위로 나눈 후, 그 기반 위에 구조화된 트리 구조를 만들어냄
- HMTL 파싱 피라미드
	- HTML 문자열이 네트워크를 통해 전달됨
	- 문자열을 문법적으로 분석함 (파싱)
	- 태그를 토큰 단위로 분리함
	- 토큰을 노드로 변환
	- 노드를 연결하여 트리 구조를 형성함
- 돔은 HTML을 그대로 보존하는 것이 아니라 HTML을 구조화된 객체의 트리로 변환하여 자바스크립트가 이를 제어할 수 있도록 만든 형태
- 우리는 이 구조를 콘솔에서도 확인할 수 있음
	- console.dir() : 자바스크립트 객체를 트리구조로 펼쳐서 속성과 메서드를 계층적으로 보여주는 도구
## HTML에서 DOM으로 
- 컴퓨터에 HTML코드를 적는 것은 웹페이지의 설계도를 만드는 것
- 사람이 보기에 이해하기 쉽지만 컴퓨터에게는 단순한 문자에 불과
- 브라우저는 이 HTML을 읽고 해석하여 하나의 객체 구조로 변환하는데 그 결과 만들어지는 구조물이 DOM
- HTML 문서 처리
	- 문서읽기: 브라우저는 HTML 문서를 맨 위에서부터 한 줄씩 차례로 읽음
	- 토큰생성: 각 태그를 만날 때마다 이를 토큰, 즉 작은 단위로 나눔
	- 노드생성: 열리는 태그를 보면 새 요소가 생겼다고 판단하여 새 노드를 만들고 닫히는 태그를 보면 요소가 끝났다고 판단하여 부모로 돌아감
		- 이 과정을 반복하면서 하나의 트리 구조 즉 부모와 자식 관계를 가진 구조를 만듦
	- 문서 렌더링: 브라우저가 처리된 문서를 표시함
## 구조와 API를 왜 분리해서 이해해야 할까
- 돔을 구성하는 핵심요소 구조와 인터페이스 역할을 하는 API
- 돔은 구조물 -> HTML로 작성된 코드는 브라우저에 의해 돔 트리라는 건물로 조립됨
- 자바스크립트는 공구 -> 자바스크립트의 메서드들은 돔이라는 건물을 수정하고 확장하는 도구
- 자바스크립트로 돔을 조작한다는 것은 구조 안의 내용을 바꾸는 것이고 이를 위한 도구가 돔 API
- 돔 API는 브라우저가 돔을 조작하기 위해 제공하는 도구
- 돔 API는 우리가 만든 함수가 아니라, 브라우저가 미리 정해놓은 공식 함수
	- 우리가 이름을 바꿀 수 없고 모든 브라우저에서 동일하게 작동해야 함
## 돔은 자바스크립트일까? 브라우저 안의 동작 원리
- 돔은 자바스크립트 언어 자체에 포함된 것이 아니라 웹 브라우저가 제공하는 기능
- 자바스크립트는 단지 이 돔이라는 기능을 사용할 수 있도록 허용받은 언어
- 자바스크립트는 객체를 다루는 일반적인 언어지만 브라우저는 HTML을 해석해 document, window 같은 특수 객체를 만들어 자바스크립트에 제공함
- 예를 들어 documnet.getElementById()와 같은 메서드는 자바스크립트 자체의 기능이 아니라 브라우저가 제공하는 돔 API 덕분에 사용 가능한 것
- 이러한 메서드는 자바스크립트 문법으로 접근하고 조작할 수 있지만 그 실체는 브라우저가 만들어 놓은 돔 구조와의 연결 다리, 즉 자바스크립트와 돔을 이어주는 브릿지 역할
- 자바스크립트는 원래 돔을 인식하거나 해석할 능력이 있는 언어가 아니며 단지 브라우저가 제공해주는 문서 객체를 다룰 수 있을 뿐임
- 돔은 브라우저가 HTML을 해석해 만든 문서 객체 트리
- 자바스크립트는 그 구조를 조작할 수 있도록 브라우저가 연결해준 API를 활용하는 도구이자 언어
## 돔을 둘러싼 두 가지 시선 - 객체인가 구조인가
- 돔을 이야기할 때 한 편으로는 트리구조로 보고 또 한 편으로는 객체처럼 다루는 방식을 사용 -> 돔은 구조이면서 동시에 객체들의 집합 즉 구조화된 객체 트리
- 객체로 보는 시선은 그것이 조작 가능한 속성과 메서드를 가진 실체임을 강조
	- 객체란 이름과 값을 가진 데이터 덩어리
- 구조로 보는 것은 그것이 웹 페이지의 계층적 조직을 나타냄을 강조
- 돔은 하나의 큰 트리구조를 이루고 있으며, 그 안의 각 요소는 객체로서 정보를 가지며, 기능을 수행할 수 있는 자바스크립트 객체로 표현됨
## document 객체는 어떻게 만들어지고 무슨 일을 할까
- document란 웹페이지의 구조와 구속 요소들을 한눈에 알 수 있도록 정리한, 브라우저가 자동으로 만들어주는 전체 지도
- 브라우저는 HTML을 트리 구조로 해석한 뒤, 이를 객체로 메모리에 저장함
- 이 메모리에 만들어진 트리 전체를 가리키는 것이 document
- 따라서 자바스크립틑로 무언가를 하려면 document부터 시작해야함
- document가 없으면 우리가 찾고 싶은 요소가 어디 있는지를 알 수 없기 때문
- document는 모든 요소 탐색의 출발점
- 브라우저에서 문서 전체를 대표하는 중앙 관리자 역할을 함

- HMTL을 브라우저에 띄우는 순간 브라우저는 그것을 해석해서 DOM 트리를 만들고 그 트리 전체를 대표하는 다큐먼트 객체를 자동으로 자바스크립트 코드에서 사용할 수 있게 전역에 등록해 줌
- document는 HTMLDocument 클래스의 인스턴스
- HTMLDocument라는 설계도(class)를 바탕으로 실제 메모리에 만들어진 객체(instance)라는 의미
- 브라우저가 HTML을 해석한 결과로 document라는 실제 DOM객체가 생성됨
## DOM은 왜 트리인가? - 부모, 자식, 형제 노드의 구조 이해
- 트리란 어떤 하나의 기준점 루트가 있고 그 아래로 여러 개의 항목이 가지처럼 나뉘는 형태
- HMTL 문서를 보면 중첩된 구조를 갖고 있고 브라우저가 이를 트리처럼 변환해서 이해함
- DOM이란 문서를 객체처럼 다루기 위해 트리 구조로 만든 것이며, 각 HTML 요소를 하나의 노드처럼 다룰 수 있게 해줌
- HTML문서를 자바스크립트 코드로 다룰 수 있도록 문서 전체를 객체 형태로 바꿔놓은 구조이기 때문에 DOM이라고 부름
- 이 트리를 구성하는 각각의 조각을 노드라고 함
	- div 태그 뿐 아니라 텍스트, 주석, 속성 등도 각기 다른 종류의 노드로 포함됨
- 부모노드: 어떤 노드가 다른 노드를 감싸고 있을 때, 그 감싸고 있는 쪽을 부모 노드라고 부름
- 자식노드: 반대로, 부모 노드 안에 포함된 노드들은 그 부모의 자식 노드라고 함
- 형제노드: 같은 부모를 공유하는 노드들은 서로 형제 노드 
- DOM 탐색을 위한 기본 속성들
	- .parentNode: 현재 노드의 부모 노드 찾기
	- .childNodes: 현재 노드의 모든 자식 노드 확인, 줄바꿈 텍스트도 # text로 반환
	- .firstChild/ .lastChild: 첫 번째, 마지막 자식 노드 가져옴
	- .nextSibling: 다음 형제 노드 찾기
	- .previousSibling: 이전 형제 노드 찾기
	- nextElementSibling: 줄바꿈 같은 텍스트 노드 때문에 예기치 않은 오류가 발생할 수 있으므로 이를 사용해서 요소만 반환하는 것이 더 안전함
- DOM 주요 노드 정리
	- Element 노드: 눈에 보이는 HTML태그, 건물의 뼈대
	- Text 노드: 태그 안의 글자, 건물 안의 내용물
	- Comment 노드: 보이지 않는 주석, 벽에 붙은 메모
	- Attribute 노드: 태그의 속성 정보, 건물 옆의 표지판
## getElementById()
- 가장 빠르고 기본적인 선택자
- id 속성값을 가진 단 하나의 요소를 가져오는 함수
- 특정한 하나의 요소만 정확하게 집어내고 싶을 때 사용하는 도구
- id는 문서 전체에서 단 한 번만 사용해야 함
	- getElementById는 여러 개의 id가 존재하더라도 가장 먼저 발견된 단 하나의 요소만 가져오기 때문
## getElementsByClassName()
- 같은 class 속성을 가진 모든 요소들을 한꺼번에 가져오는 메서드
- 여러 요소들을 반환하기 때문에 단일 dom요소가 아닌 HTMLCollection 객체로 결과가 반환됨
## get ElementsByTagName()
- 같은 태그 이름을 가진 요소들을 모두 찾아서 모아줌
- 예를 들면 < div >, < p > 등과 같은 태그 이름을 가진 요소들을 모아주는 것
- 여러 요소들을 반환하기 때문에 단일 dom요소가 아닌 HTMLCollection 객체로 결과가 반환됨
- HTMLCollection은 유사 배열로 인덱스로 접근하고 .length로 개수 확인은 가능하지만 forEach, map과 같은 배열 메서드는 사용할 수 없음
- 반복할 때는 주로 for 루프나 for..of 구문을 사용
- 전체 문서뿐 아니라 특정 요소 내부에서만 검색하도록 범위를 제한할 수도 있음
## querySelector - CSS 문법으로 단일 요소 잡아내기
- 웹 개발을 하다 보면 클래스명, 태그명, 아이디명 등을 조합해 특정 요소를 정확히 선택하고 싶을 때가 많음
- 그렇게 복잡한 요소를 선택하고 싶을 때 사용하는 것이 바로 querySelector()
- 가장 먼저 일치하는 단 하나의 요소를 반환
- CSS 선택자 문법을 그대로 사용할 수 있기 때문에, 클래스, 아이디, 태그, 조합 선택 등 직관적이고 유연한 선택이 가능함
- querySelector(#main) 혹은 querySelector(.btn) 처럼 CSS에서 사용하는 클래스 문법이나 아이디 선택자를 사용할 수 있음
- querySelector()의 가장 큰 강점은 여러 선택자를 자유롭게 조합할 수 있다는 것
- 더 정교하고 유연한 요소 선택이 가능함
- document.querySelector("#container .highlighted"); 와 같이 id가 container인 요소 내부에서 클래스 명이 highlighted인 첫 번째 요소를 한 줄로 선택할 수 있게 됨
- querySelector()는 특정 요소 내부에서도 사용이 가능함
	- 전체 문서가 아니라 범위를 제한해 요소를 선택할 수 있음
	- 복잡한 구조에서도 정확하고 효올적인 선택 가능
- querySelector()는 CSS 선택자 문법을 그대로 사용할 수 있어서 직관적이고 정확하게 원하는 요소를 찾을 수 있다는 장점
## querySelectorAll()
- 모든 일치 요소를 한꺼번에 선택할 수 있는 메서드
- 같은 구조나 스타일을 가진 요소들이 여러 개 반복되는 경우가 있는데 이 경우 querySelector()처럼 하나의 요소만 선택하는 방식은 매우 비효율적
- querySelectorAll()은 CSS 선택자에 일피하는 모든 요소를 한 번에 선택함
- querySelectorAll()의 반환값은 NodeList로 특정 클래스를 가진 요소들을 선택하면 NodeList형태의 목록이 변수에 담김
	- NodeList는 번호가 붙은 요소들의 집합처럼 보이지만, 진짜 배열은 아니기 때문에 forEach()는 가능하지만 map(), filter()과 같은 배열 전용 메서드는 사용할 수 없음
## HTMLCollection VS NodeList
- 여러 요소를 한꺼번에 선택할 때 자동으로 생성되는 구조이며, 겉보기엔 비슷하지만 실제 동작은 꽤 다르게 작동함
- 어떤 메서드를 사용하느냐에 따라서 반환 타입과 함께 DOM변화 반영 방식도 자동으로 결정됨
- HTMLCollection
	- getElemenstByTagName()
	- getElementsByClassName()
	- documents.forms()
	- document.images()
	- DOM 변화 반영 -> 실시간 갱신
	- 라이브 컬렉션
	- DOM이 바뀌면 목록도 함께 변함
	- 실시간 DOM 상태를 감지할 때는 매우 유용하지만 반복문 중에 DOM을 변경하면 요소의 순서가 밀리거나 건너뛰는 현상이 생길 수 있음 -> 순회 중 DOM 변경 시에는 주의가 필요
		- 이를 해결하기 위해서 HTMLCollection()을 배열로 복사해서 사용할 수 있음
		- 이때 사용하는 메서드가 바로 Array.from()
	
- NodeList
	- querySelectorAll()
	- childNodes()
	- getElementsByName()
	- DOM 변화 실시간 반영 하지않고 선택 시점의 상태 고정
	- 정적 컬렉션
	- 선택 당시 상태만 유지됨
	- DOM 변화와 무관하게 유지되기 때문에 반복 중 요소를 추가하거나 삭제해도 순서가 꼬이지 않음
	- 중간에 리스트가 바뀌는 혼란 없이 안정적으로 순회하며 조작할 수 있음
	- 특히 삭제 작업이나 DOM 변경이 동시에 일어나는 경우 한 번 정해진 기준으로 작업할 때 매우 유용
	- forEach나 .length 등 사용가능
## getElementsByTagName()
- HTML 문서 안의 특정 태그들을 한꺼번에 선택할 때 자주 사용됨
- 지정한 태그 이름을 기준으로 해당하는 모든 요소들을 한꺼번에 찾아줌
- 선택한 모든 요소가 HTMLCollection으로 반환
	- 배열처럼 보이지만 배열은 아니며, Live 상태이다
- HTMLCollection은 배열처럼 인덱스로 접근 가능하며 각 요소에 .textContent나 .style을 사용해 직접 조작할 수 있음
- " * " 를 사용하면 해당 요소 내부의 모든 태그요소를 한꺼번에 선택할 수 있음
## getElementsByClassName()
- 특정 클래스 이름을 가진 HTML요소들을 모두 한꺼번에 가져오는 메서드
- 단일 클래스뿐만 아니라 공백으로 구분된 여러 클래스 이름도 전달할 수 있음
- getElementsByTagName()와 비슷함. 어떤 요소를 가져오느냐의 차이
## querySelector과 querySelectorAll
- 이 두 메서드는 CSS 선택자 문법을 그대로 사용할 수 있기 때문에 복잡한 구조에서도 원하는 요소를 직관적으로 선택할 수 있음
- querySelector
	- 조건에 맞는 첫 번째 요소 하나만 선택
	- 중요한 점은 가장 먼저 매칭되는 요소 하나만 반환한다는 것
- querySelectorAll
	- 조건에 맞는 모든 요소들을 한꺼번에 선택
	- CSS 선택자에 맞는 모든 요소를 가져와서 NodeList로 반환
- 구조 선택자
	- 같은 태그가 반복될 때, 그 중에서 순서나 위치에 따라 특정 요소만 선택할 수 있게 해주는 CSS 문법
	- 첫 번째 요소만 선택하고 싶다면 .first-of-type 또는 :nth-of-child(1)과 같은 구조 선택자 사용 가능
- 속성 선택자
	- 조건을 추가해 더 정확하고 세밀하게 요소를 선택하고 싶을 때
	- 요소에 지정된 특정 속성과 값을 기준으로 보다 정밀하게 원하는 요소만 선택할 수 있도록 해줌
	- [ 속성이름 = "값" ] 형태로 조건을 걸 수 있어 동적 콘텐츠가 많은 페이지에서 정밀한 선택에 매우 유용함
## DOM 트리 구조를 따라 부모나 형제 요소를 구조적으로 찾기
-  .parentNode : 해당 요소가 포함된 상위 요소인 부모 요소를 의미
-  .previousElementSibling : 해당 요소 바로 앞에 있는 형제 요소 의미
	- DOM 트리에서 같은 부모를 공유하며 나란히 위치한 요소를 형제요소라고 함
-  .parentNode.children : 부모요소의 모든 자식요소들을 배열처럼 가져옴
	- 해당 노드의 자식 요소들이 HTMLCollection에 포함되어 반환됨
-  .children VS .childNodes
	- .children은 요소 노드만 필터링해서 반환함 
		- ex) < li >HOME< /li >, < li >ABOUT< /li > ...
	- .childNodes는 텍스트 노드, 주석 노드까지 포함한 모든 노드타입을 포함함
		- 반복문 사용 시 # text, 주석 노드 등이 섞일 수 있어 예상치 못한 오류 발생 가능성이 있음
		- < li >HOME< /li >, < li >ABOUT< /li >, # text(줄바꿈 공백)...
