## 소개
- 자바스크립트는 웹페이지에 생동감을 불어넣기 위해 만들어진 프로그래밍 언어
- 자바스크립트로 작성한 프로그램을 스크립트라고 하며 스크립트는 웹 페이지의 HTML안에 작성할 수 있는데, 웹 페이지를 불러올 때 스크립트가 자동으로 실행됨
- 스크립트는 특별한 준비나 컴파일 없이 문자 형태로 작성할 수 있고 실행도 가능
- 자바스크립트는 브라우저뿐만 아니라 서버에서도 실행할 수 있음
	- 이 외에도 자바스크립트 엔진 프로그램이 들어있는 모든 디바이스에서 동작
- 브라우저에는 자바스크립트 가상 머신이라 불리는 엔진 내장
	- V8: chrome과 opera
	- SpiderMonkey: firefox
	- Trident, chakra: IE
## 엔진의 동작 원리
1. 엔진(브라우저 내장 엔진)이 스크립트를 읽음(파싱)
2. 읽어 들인 스크립트를 기계어로 전환(컴파일)
3. 기계어로 전환된 코드가 실행 => 기계어로 전환되었기 때문에 실행 속도가 빠름
- 엔진은 프로세스 각 단계마다 최적화 진행
- 컴파일이 끝나고 실행 중인 코드를 감시하면서, 이 코드로 흘러가는 데이터를 분석하고 분석 결과를 토대로 기계어로 전환된 코드를 다시 최적화하기도 함
## 브라우저에서 할 수 있는 일과 없는 일
- 할 수 있는 일
	- 페이지에 새로운 HTML을 추가하거나 기존 HTML, 혹은 스타일 수정하기
	- 마우스 클릭이나 포인터의 움직임, 키보드 키 눌림 등과 같은 사용자 행동에 반응하기
	- 네트워크를 통해 원격 서버에 요청을 보내거나, 파일 다운로드, 업로드하기
	- 쿠키를 가져오거나 설정하기, 사용자에게 질문을 건네거나 메시지 보여주기
	- 클라이언트 측에 데이터 저장하기(로컬 스토리지)
- 브라우저에서 할 수 없는 일
	- 웹 페이지 내 스크립트는 디스크에 저장된 임의의 파일을 읽거나 쓰고, 복사하거나 실행할 때 제약을 받을 수 있음 => 운영체제가 지원하는 기능을 브라우저가 직접 쓰지 못하게 막혀있기 때문
	- 카메라나 마이크 같은 디바이스와 상호작용하려면 사용자의 명시적인 허가가 있어야 함
	- 브라우저 내 탭과 창은 대개 서로의 정보를 알 수 없음 그런데 자바스크립트를 사용해 한 창에서 다른 창을 열 때는 예외 발생 => 이 경우에도 도메인이나 프로토콜, 포트가 다르다면 페이지에 접근할 수 없음
	- 타 사이트나 도메인에서 데이터를 받아오는 것은 불가능 혹은 원격 서버에 명확히 승인을 해줘야 함
## 자바스크립트만의 강점
- HTML/CSS와 완전히 통합할 수 있음
- 간단한 일은 간단하게 처리할 수 있게 해줌
- 모든 주요 브라우저에서 지원하고, 기본 언어로 사용됨
## 자바스크립트 기본
- 자바스크립트 코드의 양이 많은 경우엔, 파일로 소분하여 저장할 수 있음
-  `<`script  `src` `= "`/path/to/script.js`"` >`  `</`script >`
	- 분해해 놓은 각 파일은 src 속성을 통해 HTML에 삽입함
	- src에는 파일 경로나 URL이 들어갈 수 있음
## 코드 구조
- statement 문
	- 문은 어떤 작업을 수행하는 문법구조와 명령어
	- 서로 다른 문은 세미콜론으로 구분함
	- 줄 바꿈이 있으면 세미콜론이 자동으로 존재한다고 가정
## 엄격 모드
- ES5가 등장하면서 새로운 기능이 추가되고 기존 기능 중 일부가 변경됨
- 기존 기능을 변경하였기 때문에 하위 호환성 문제 발생 -> 변경 사항 대부분은 ES5기본 모드에선 활성화 되지 않도록 설계
- 대신 Use strict라는 특별한 지시를 통해 엄격모드를 활성화 했을 때만 이 변경사항이 활성화되게 해둠
- use strict라는 지시자가 최 상단에 오면 스크립트 전체가 모던한 방식으로 동작함
- 일단 엄격 모드가 적용되면 돌이킬 방법은 없음
- 코드를 클래스와 모듈을 사용해 구성하면 자동으로 적용되기에 이를 생략해도 됨
## 변수와 상수
- 변수는 데이터를 저장할 때 쓰이는 이름이 붙은 저장소 => 온라인 쇼핑몰 애플리케이션을 구축하는 경우 상품이나 방문객 등의 정보를 저장할 때 변수를 사용함
- let
	- let message = 'hello';
	- 변수는 한 번만 선언해야 함
	- 같은 변수를 여러 번 선언하면 에러가 발생
- var
	- let과 거의 동일하게 동작
- 변수명에는 오직 문자와 숫자, 그리고 기호 $과 _ 만 들어갈 수 있음
- 변수명은 숫자로 시작해서는 안되고 하이픈을 사용할 수 없음
- 예약어 목록에 있는 단어 역시 변수명으로 사용할 수 없음

- 상수
	- 변화하지 않는 변수를 선언할 때 사용
	- const message = 'hello';
	- 상수는 재할당할 수 없으므로 상수를 변경하고자 하면 에러 발생
	- 대문자 상수는 하드 코딩한 값의 별칭을 만들 때 사용
## 자료형
- 자바스크립트의 변수는 자료형에 관계없이 모든 데이터일 수 있음
- 따라서 변수는 어떤 순간에 문자열일 수 있고 다른 순간엔 숫자가 될 수도 있음
- 자료의 타입은 있지만 변수에 저장되는 값의 타입은 언제든지 바꿀 수 있는 동적 타입언어
- 숫자형
	- 숫자형은 정수 및 부동소수점 숫자를 나타냄
	- 숫자형과 관련된 연산은 다양한데, 곱셈, 나눗셈, 덧셈, 뺄셈 등이 대표적
	- 숫자형에는 일반적인 숫자 외에 Infinity, -Infinity, NaN과 같은 특수 문자값이 포함됨 
	- Infinity
		- 어떤 숫자보다 더 큰 특수 값 무한대
		- 어느 숫자든 0으로 나누면 무한대를 얻을 수 있음
	- NaN
		- 계산 중에 에러가 발생했다는 것을 나타내주는 값
		- 부정확하거나 정의되지 않은 수학 연산을 사용하면 계산 중에 에러가 발생하는데 이때 NaN이 반환됨
- BigInt
	- 내부 표현 방식 때문에 자바스크립트에서는 숫자형으로 나타낼 수 없는 범위가 있음
	- 위 자료형은 길이에 상관없이 정수를 나타낼 수 있음
	- BigInt 값은 정수 리터럴 끝에 n을 붙이면 만들 수 있음
- 문자형
	- 문자열을 따옴표로 묶어서 나타냄
	- 큰 따옴표와 작은 따옴표는 차이를 두지 않음
	- 백틱으로 변수나 표현식을 감싼 후 ${ }안에 넣어주면 원하는 변수나 표현식을 문자열 중간에 손쉽게 넣을 수 있음
	- ${ } 안에는 변수나 수학 관련 표현식을 넣을 수 있음
- 불린형
	- true와 false 두 가지 값밖에 없는 자료형
	- 긍정이나 부정을 나타내는 값을 저장할 때 사용함
	- 비교 결과를 저장할 때도 사용됨
- null값
	- 어느 자료형에도 속하지 않는 값
	- null 값은 오로지 null값만 포함하는 별도의 자료형을 만듦
- undefined 값
	- null처럼 자신만의 자료형을 형성
	- 변수는 선언했지만 값을 할당하지 않았을 때
	- 개발자가 변수에 undefined를 명시적으로 할당하는 것도 가능
- 객체와 심볼
	- object(객체)형은 특수한 자료형
	- 객체형을 제외한 다른 자료형은 문자열이든 숫자든 한 가지만 표현할 수 있기 때문에 원시 자료형이라고 부름
	- 반면 객체는 복잡한 개체나 데이터 컬렉션을 표현할 수 있음
	- 심볼형은 객체의 고유한 식별자를 만들 때 사용됨 
- typeof 연산자
	- 인수의 자료형을 반환
	- 변수의 자료형을 빠르게 알아내고자 할 때 혹은 자료형에 따라 처리 방식을 다르게 하고 싶을 때 유용
	- typeof x를 호출하면 인수의 자료형을 나타내는 문자열을 반환
	- typeof null의 결과는 object
		- null은 별도의 고유한 자료형을 가지는 특수 값으로 객체가 아니지만 하위 호환성을 유지하기 위해서 이렇게 출력됨 => 실제로는 객체가 아님
## alert, prompt, confrim을 이용한 상호작용
- alert
	- 이 함수가 실행되면 사용자가 확인(OK)를 누를 때까지 메세지를 보여주는 창이 계속 떠있게 됨
	- 메시지가 있는 창은 모달 창이라고 부름
	- 확인 버튼을 누르기 전까지는 모달 창 바깥에 있는 버튼을 누른다거나 하는 행동을 할 수 없음
- prompt
	- 브라우저에서 제공하는 prompt 함수는 두 개의 인수를 받음
	- prompt(title, [ default ])
	- 함수가 실행되면 텍스트 메시지와 입력필드, 확인, 취소 버튼이 있는 모달 창을 띄워줌
	- title: 시용자에게 보여줄 문자열
	- default: 입력 필드의 초깃값(선택값)
- confirm
	- confirm 함수는 매개변수로 받은 질문과 확인 및 취소 버튼이 있는 모달 창을 보여줌
	- 사용자가 확인 버튼을 누르면 true, 그 외의 경우는 false를 반환함
## 형 변환
- 함수와 연산자에 전달되는 값은 대부분 적절한 자료형으로 자동 변환됨
- alert가 전달받은 값의 자료형과 관계없이 이를 문자열로 자동 변환하여 보여주는 것이나, 수학 관련 연산자가 전달받은 값을 숫자로 변환하는 경우가 형 변환의 대표적인 예시
- 문자형으로 변환
	- alert 메서드는 매개변수로 문자형을 받기 때문에 alert(value)에서 value는 문자형이어야 함
	- 다른 형의 값을 전달받으면 이 값은 문자형으로 자동 변환됨
	- String(value) 함수를 호출해 전달받은 값을 문자열로 변환할 수도 있음
- 숫자형으로 변환
	- 숫자형이 아닌 값에 나누기를 적용한 경우와 같이 수학과 관련된 함수와 표현식에서 자동으로 일어남
	- Number(value)함수를 이용하면 주어진 값을 숫자형으로 명시해서 변환할 수 있음
	- 숫자 이외의 글자가 들어가 있는 문자열을 숫자형으로 변환하려고 하면 그 결과는 NaN이 됨
	- undefined는 NaN
	- null은 0
	- true and false는 1과 0
	- string은 일단 문자열의 처음과 끝 공백이 제거되고 남아있는 문자열이 없다면 0, 그럴지 않다면 문자열에서 숫자를 읽음
- 불린형으로 변환
	- Boolean(value)를 호출하면 명시적으로 불리언으로의 형 변환을 수행할 수 있음
	- 숫자 0, 빈 문자열, null, undefined, NaN과 같이 직관적으로도 비어있다고 느껴지는 값들은 false가 되고 그 외의 값은 true로 변환됨
	- 문자열 "0"은 true
## 기본 연산자와 수학
- 피연산자
	- 연산자가 연산을 수행하는 대상. 이는 인수라는 용어로 불리기도 함
	- 피연산자를 하나만 받는 연산자는 단항 연산자
	- 피연산자의 부호를 뒤집는 단항 마이너스 연산자 -는 단항 연산자의 대표적인 예
- 이항 연산자
	- 두 개의 피연산자를 받는 연산자는 이항 연산자라고 부름
	- 마이너스 연산자는 이항 연산자로도 쓸 수 있음
- 수학
	- 나머지 연산자 %
		- a % b는 a를 b로 나눈 후 그 나머지를 정수로 반환해 줌
	- 거듭제곱 연산자 **
		- a ** b 를 하면 a를 b번 곱한 값이 반환
- 이항 연산자와 문자열 연결
	- 덧셈 연산자는 대개 숫자를 더한 결과를 반환
	- 이항 연산자 +의 피연산자로 문자열이 전달되면 덧셈 연산자는 덧셈이 아닌 문자열을 병합함
	- 따라서 이항 연산자를 사용할 때는 피연산자 중 하나가 문자열이면 다른 하나도 문자열로 변환된다는 점에 주의하기 
	- 이항 덧셈 연산자는 문자열 연결과 변환이라는 특별한 기능을 제공함
	- 다른 산술연산자가 오직 숫자형의 피연산자만 다루고, 피연산자가 숫자형이 아닌 경우에 그 형을 숫자형으로 바꾸는 것과는 대조적
- 2 + 2 + '1'
	- 그러나 위와 같은 경우에서는 '41'이 출력됨
	- 연산이 왼쪽에서 오른쪽으로 순차적으로 진행되기 때문에 두 개의 숫자 뒤에 문자열이 오는 경우 숫자가 먼저 더해지고 그 후 더해진 숫자와 문자열의 병합이 일어남
- 단항 덧셈 연산자
	- 숫자에는 아무 영향도 미치지 않음
	- 숫자형이 아닌 피연산자는 숫자형으로 변환함
- 연산자 우선순위
	- 동일한 기호의 단항 연산자는 이항 연산자보다 우선순위가 높다
- 할당 연산자
	- 무언가를 할당할 때 쓰이는 =도 연산자
	- 우선순위는 아주 낮음

## if와 ?를 사용한 조건 처리
- if문
	- 괄호 안에 들어가는 조건을 평가하는데, 그 결과가 true이면 코드 블럭이 실행됨
	- 조건이 true일 때 복수의 문을 실행하고 싶다면 중괄호로 코드 블록을 감싸야 함
	- 그러나 한 줄 이더라도 중괄호로 감싸면 가독성이 올라가서 좋음
- 불린형으로의 변환
	- if(...)문은 괄호 안의 표현식을 평가하고 그 결과를 불린값으로 변환함
	- 숫자 0, 빈 문자열, null, undefined, NaN은 불린형으로 변환 시 모두 false가 됨 => 이런 값들은 falsy라고 부름
	- 이 외의 값은 불린형으로 변환시 모드 true가 되므로 truthy라고 부름
- else 절
	- if 문엔 else 절을 붙일 수 있음
	- else 뒤에 이어지는 코드 블록은 조건이 거짓 일 때 실행됨
- else if로 복수 조건 처리하기
	- 유사하지만 약간씩 차이가 있는 조건 여러 개를 처리해야 할 때 사용
- 조건부 연산자 ?
	- 조건에 따라 다른 값을 변수에 할당해줘야 할 때
	- 물음표 연산자라고도 불리는 조건부 연산자를 사용하면 식을 간결하게 표현가능
	- 조건부 연산자는 ?로 표시
	- 피연산자가 세 개이기 때문에 조건부 연산자를 삼항 연산자라고 부르는 사람도 있음
- 다중 ?
	- 물음표 연산자 여러개를 연결하면 복수의 조건을 처리할 수 있음
## 논리 연산자
- ||(OR)
	- 불린값을 조작하는 데 쓰임
	- 인수 중 하나라도 true이면 true
	- 피연산자가 불린형이 아니면 평가를 위해 불린형으로 변환
	- OR 연산자와 피연산자가 여러 개인 경우에는 첫 번째 truthy를 반환하고 피연산자에 truthy가 하나도 없다면 마지막 피연산자를 반환
- &&(AND)
	- 두 피연산자가 모두 참일 때 true를 반환
	- AND 연산자와 피연산자가 여러 개인 경우 첫 번째 falsy를 반환
	- 피연산자에 falsy가 없다면 마지막 값을 번환
- AND의 우선순위가 ||보다 높음
- !(NOT)
## nullish 병합 연산자 ??

- null이나 undefined가 아닌 첫 번째 피연산자
- ||과 가장 큰 차이는 ||은 0을 falsy로 취급하여 null이나 undefined를 할당한 것과 동일하게 처리하지만 ??은 0이라는 변수가 할당된 것으로 보아 0이 출력됨
- ??의 연산자 우선순위는 5로 꽤 낮음
- 따라서 ??는 =와 ?보다는 먼저, 대부분의 연산자보다는 나중에 평가됨
## while과 for 반복문
- while 반복문
	- while (condition) { // 코드(반복문 본문이라고 불림) }
	- condition 조건이 truthy면 반복문 본문의 코드가 실행됨
- do while 반복문
	- do while 문법을 사용하면 condition을 반복문 본문 아래로 옮길 수 있음
	- do { // 반복문 본문 } while (condition)
- for 반복문
	- for(begin; condition; step) { //반복문 본문 }
	- begin
		- 반복문에 진입할 때 단 한 번 실행됨
	- condition
		- 반복마다 해당 조건이 확인됨
		- false이면 반복문을 멈춤
	- body
		- 반복문 본문
		- condition이 truthy일 동안 계속해서 실행됨
	- step
		- i++
		- 각 반복의 body가 실행된 후 실행됨
	- begin을 실행함 -> condition이 truthy -> body 실행 -> step 실행 위 과정 반복
	- 구성요소 생략하기
		- 반복문이 시작될 때 아무것도 할 필요가 없으면 begin을 생략하는 것이 가능
		- step 역시 생략 가능
		- 모든 구성요소를 생략하는 것도 가능하지만 for( ;; )이렇게 세미콜론을 넣어줘야 함
- 반복문 빠져나오기
	- break를 사용하면 언제든 원하는 때에 반복문을 빠져나올 수 있음
	- 반복문이 증시 중단되고 제어 흐름이 반복문 아래 첫 번째 줄로 이동
- 다음 반복으로 넘어가기
	- continue
	- 전체 반복문을 멈추지 않고 현재  실행 중인 이터레이션을 멈추고 반복문이 다음 이터레이션을 강제로 실행시키도록 함
- labelName: for (...) { }
	- 레이블은 반복문 앞에 콜론과 함께 쓰이는 식별자
	- if (!input) break label;
	- 레이블이 붙은 반복문을 찾고 해당 반복문을 빠져나오게 해줌
- for (let i = 2; i <=10; i++){ if (i % 2 == 0) {alert( i );} }
	- 반복문을 사용해서 2부터 10까지 숫자 중 짝수만 출력하는 것

## switch문
- 복수의 if 조건문은 switch문으로 바꿀 수 있음
- switch문은 하나 이상의 case문으로 구성됨
- 대개 default문도 있지만 필수는 아님
- switch( x ) { case 'value 1': ... [ break ;] case 'value 2': ... [ break ;] default:  }
	- 변수 x값과 첫 번째 case문의 값 value1을 비교한 후 두 번째 case문의 값 value2와 비교 => 위 과정 반복
	- case문에서 변수 x의 값과 일치하는 값을  찾으면 해당 case문의 아래 코드가 실행됨
	- 이때, break문을 만나거나 switch 문이 끝나면 코드의 실행은 멈춤
	- 값과 일치하는 case문이 없다면 default가 실행( default문이 있는 경우 )
- case 문에 break문이 없는 경우
	- 조건에 부합하는지 여부를 따지지 않고 이어지는 case문을 실행

## 객체
- 자바스크립트에는 8가지 자료형이 있음
- 이 중 객체형을 제외한 나머지는 오직 하나의 데이터만 담을 수 있어서 원시형이라고 부름
- 객체형은 다양한 데이터를 담을 수 있음
	- 키로 구분된 데이터 집합이나 복잡한 개체를 저장할 수 있음
	- 객체는 자바스크립트 거의 모든 면에 녹아있는 개념이므로 자바스크립트를 잘 다루려면 객체를 잘 이해하고 있어야 함
- 객체는 중괄호를 이용해 만들 수있음
- 중괄호 안에는 키:값 쌍으로 구성된 프로퍼티를 여러개 넣을 수 있는데, 키에는 문자형, 값엔 모든 자료형이 허용됨 
- 프로퍼티 키는 프로퍼티 이름 혹은 식별자라고도 부름
- let user = { name: "john", ... } 이런식으로 객체를 선언하는 것을 객체 리터럴
- 점 표기법을 사용하면 프로퍼티 값을 읽을 수 있음
- delete user.age; 으로 삭제할 수도 있음
- const로 선언된 객체는 다른 데이터 타입과 다르게 수정될 수 있음
- 여러 단어를 조합해 프로퍼티 이름을 만든 경우엔 프로퍼티 이름을 따옴표로 묶어야 함
	- 위 경우엔 점 표기법을 사용해 프로퍼티 값을 읽을 수 없음
	- 이럴땐 users["like birds"]와 같이 대괄호 표기법 사용
- 계산된 프로퍼티
	- 객체를 만들 때 객체 리터럴 안의 프로퍼티 키가 대괄호로 둘러싸여 있는 경우 이를 계산된 프로퍼티라고 부름
	- let bag = { [ fruit ] : 5, } 
		- 변수 fruit에서 프로퍼티 이름을 동적으로 받아옴
		- alert ( bag.apple ); => fruit에 apple이 할당되었다면 5가 출력됨
- for in 반복문
	- 이를 사용하면 객체의 모든 키를 순회할 수 있음
	- for (key in object ) {  }
- 객체 정렬방식
	- 정수 프로퍼티는 자동으로 정렬되고 그 외의 프로퍼티는 객체에 추가한 순서대로 정렬됨
## 참조에 의한 객체 복사
- 객체와 원시 타입의 근본적인 차이 중 하나는 객체는 참조에 의해 저장되고 복사된다는 것
- 반면 원시값은 값 그대로 저장, 할당되고 복사됨
- 즉, 객체는 변수에 객체가 그대로 저장되는 것이 아니라 객체가 저장되어 있는 메모리 주소인 객체에 대한 참조 값이 저장된다는 의미
- 따라서 객체가 할당된 변수를 복사할 땐 객체의 참조 값이 복사되고 객체는 복사되지 않음
	- 객체에 접근하거나 객체를 조작할 땐 여러 변수를 사용할 수 있음
- 그렇다면 기존에 있던 객체와 똑같으면서 독립적인 객체를 만들고 싶다면?
	- 자바스크립트는 객체 복제 내장 메서드를 지원하지 않기 때문에 새로운 객체를 만든 다음 기존 객체의 프로퍼티들을 순회해 원시 수준까지 프로퍼티를 복사하면 됨
	- Object.assign( dest, [ src1, src2, src3 .... ] )
		- dest는 목표로 하는 객체
		- 이어지는 인수는 복사하고자 하는 객체 
		- src1, src2.. 의 프로퍼티를 dest에 복사
		- 목표 객체에 동일한 이름을 가진 프로퍼티가 있는 경우 기존 값이 덮어씌워짐
## 가비지 컬렉션
- 자바스크립트는 도달 가능성이라는 개념을 사용해 메모리 관리를 수행함
- 도달가능한 값은 어떻게든 접근하거나 사용할 수 있는 값을 의미함
- 도달 가능한 값은 메모리에서 삭제되지 않음
- 루트
	- 태생부터 도달 가능하기 때문에 명백한 이유없이는 삭제되지 않는 값
	- 현재 함수의 지역 변수와 매개변수
	- 중첩 함수의 체인에 있는 함수에서 사용되는 변수와 매개변수
	- 전역 변수
- 루트가 참조하는 값이나 체이닝으로 루트에서 참조할 수 있는 값은 도달가능한 값이 됨
- 가비지 컬렉터는 모든 객체를 모니터링하고 도달할 수 없는 객체는 삭제함
## 메서드와 this
- 객체는 사용자, 주문 등과 같이 실제 존재하는 개체를 표현하고자 할 때 생성됨
- 함수 표현식으로 함수를 만들고 객체 프로퍼티에 함수를 할당한 후 객체에 할당된 함수를 호출하면 함수가 동작함
- 이렇게 객체 프로퍼티에 할당된 함수를 메서드라고 함
- this
	- 메서드는 객체에 저장된 정보에 접근할 수 있어야 제 역할을 할 수 있음
	- 메서드 내부에서 this 키워드를 사용하면 객체에 접근할 수 있음
	- this값은 런타임에 결정됨
	- 컨텍스트에 따라 달라짐
	- 동일한 함수라도 다른 객체에서 호출했다면 this가 참조하는 값이 달라짐
## new 연산자와 생성자 함수
- 객체 리터럴을 사용하면 {...} 객체를 쉽게 만들 수 있음
- new 연산자와 생성자 함수를 사용하면 유사한 객체 여러 개를 쉽게 만들 수 있음
- 생성자 함수는 함수를 통해서 객체를 찍어내는 공장 역할을 함
- 생성자 함수의 관례
	- 함수 이름의 첫 글자는 대문자로 시작한다
	- 반드시 new 연산자를 붙여 실행한다
- 생성자 함수엔 보통 return 문이 없음
- 반환해야 할 것들은 모두 this에 저장되고 this는 자동으로 반환되기 때문에 반환문을 명시적으로 써 줄 필요가 없음
	- 그런데 만약 객체를 return한다면 this대신 객체가 반환됨
	- 원시형을 return하면 return문이 무시됨
## 옵셔널 체이닝 '?'
- 옵셔널 체이닝을 사용하면 프로퍼티가 없는 중첩 객체를 에러없이 안전하게 접근할 수 있음
- ?. 은 ?. 앞의 평가 대상이 undefined나 null이면 평가를 멈추고 undefined를 반환함
- 예를 들어 let user = { }; 으로 주소 정보가 없는 사용자가 있음
	- alert ( user?.adress?.street ); 을 하면 에러가 발생하지 않음
- ?. 앞의 변수는 꼭 선언되어 있어야 함
## 심볼형
- 객체 프로퍼티 키로 오직 문자형과 심볼형만을 허용함
- 숫자형, 불린형 모두 불가능
- 지금까지 살펴본 것은 문자형 객체 프로퍼티 키
- 심볼
	- 유일한 식별자를 만들고 싶을 때 사용
	- Symbol( )을 사용하면 심볼값을 만들 수 있음
- let id = Symbol( "id" )
	- 심볼 id에는 "id"라는 설명이 붙음
	- 심볼은 유일성이 보장되는 자료형이기 때문에 설명이 동일한 심볼을 여러 개 만들어도 각 심볼값은 다름
	- 심볼에 붙이는 설명(심볼 이름)은 어떤 것도 영향을 주지 않는 이름표 역할만을 함
	- 심볼은 다른 자료형으로 자동 형 변환이 되지 않아서 toSting과 같은 메서드를 명시적으로 사용해줘야 함
- 객체 리터럴을 사용해 객체를 만든 경우, 대괄호를 사용해 심볼형 키를 만들어야 함
	- let id = Symbol("id");
	- let user = { name: "john", [ id ] : 123 }
	- 즉, 객체의 프로퍼티 키로 심볼을 쓸 때는 대괄호로 감싸주어야 함
- 심볼은 for in에서 배제됨
- 그러나 Object.assign은 키가 심볼인 프로퍼티를 배제하지 않고 객체 내 모든 프로퍼티를 복사함
- 전역 심볼
	- Symbol.for("id")
	- 심볼이 존재하지 않으면 새로운 심볼을 만들기
	- 이름이 같은 심볼이 같은 개체를 가리키길 원하는 경우 위 메서드 사용
	- 전역 심볼 레지스트리
## 객체를 원시형으로 변환하기
- 객체끼리 더하는 연산을 하거나 alert로 객체를 출력할 때는 자동 형 변환이 일어남
- 객체는 원시값으로 변환되고 그 후 의도한 연산이 수행됨
- 객체는 논리 평가 시 true를 반환함
- 숫자형으로의 형 변환은 객체끼리 빼는 연산을 할 때나 수학 관련 함수를 적용할 때 일어남
	- 예를 들어 Date 객체끼리 차감하면(뺄셈) 두 날짜의 시간 차이가 반환됨
- 문자형으로의 형 변환은 대개 alert(obj)와 같이 객체를 출력하려고 할 때 일어남
- ToPrimitive
	- 특수 객체 메서드를 사용하면 숫자형이나 문자형으로의 형 변환을 원하는 대로 조절할 수 있음
- [Symbol.toPrimitive]
	- 객체를 숫자나 문자열 같은 원시값으로 변환해야할 때 자바스크립트 엔진이 찾아쓰는 특별한 주문서(메서드)
	- `alert(obj)` 또는 `obj + 10` 와 같ㅇ느 경우 자바스크립트는 객체를 어떤 값으로 바꿔줘야할지 고민함
	- 이때 이 메서드가 실행되면서 어떤 형으로 바꿀지 규칙을 정해줄 수 있음
	- let = user = { name: "철수", money: 300, [ Symbol.toPrimitive ] ( hint ){  if ( hint === "string" ) {return this.name} return this.money; }};
	- 위 경우 문자열을 변환할 때는 이름을 반환하고 숫자로 변환할 때는 돈을 반환한다 
	- alert(user); // 철수 출력
	- console.log( user + 5000 ) // 5300 출력
## 원시값의 메서드
- 자바스크립트는 원시값(문자열, 숫자 등)을 마치 객체처럼 다룰 수 있게 해줌
- 원시값에도 객체에서처럼 메서드를 호출할 수 있음
- 원시값
	- 원시형 값
	- 문자, 숫자, bigint, 불린, 심볼, null, undefined 형으로 총 일곱가지
- 객체
	- 프로퍼티에 다양한 값을 저장할 수 있음
	- { name: "john" }와 같이 중괄호를 사용해 만들 수 있음
	- 자바스크립트에는 여러 종류의 객체가 있는데 함수도 객체의 일종
	- 객체의 장저 중 하나는 함수를 프로퍼티로 저장할 수 있다는 것
- 원시값을 객체처럼 사용하기
	- 문자열이나 숫자와 같은 원시값을 다뤄야하는데, 메서드를 사용하면 작업을 수월하게 할 수 있음
	- 그런데 원시값은 가능한 빠르고 가벼워야 함
	- 이를 해결하기 위한 방법
		- 원시값은 원시값 그대로 남겨둬 단일 값 형태를 유지함
		- 문자열, 숫자, 불린 심볼의 메서드와 프로퍼티에 접근할 수 있도록 언어 차원에서 허용
		- 이를 위해 원시값이 메서드나 프로퍼티에 접근하려 하면 추가 기능을 제공해주는 특수한 객체 원시래퍼객체를 만들어줌 => 이 객체는 곧 삭제됨
	- 래퍼 객체
		- 래퍼 객체는 원시 타입에 따라 종류가 다양함
		- 각 래퍼 객체는 원시 자료형의 이름을 그대로 차용해 String, Number, Boolean, Symbol 이라고 부름
		- 래퍼 객체마다 제공하는 메서드 역시 다름
	- str.toUpperCase( )
		- 인수로 받은 문자열의 모든 글자를 대문자로 바꿔주는 매서드
		- 1. 문자열 str은 원시값이므로 원시값의 프로퍼티에 접근하는 순간 특별한 객체가 만들어짐
		- 이 객체는 문자열의 값을 알 고 있고 toUpperCase와 같은 유용한 메서드를 가지고 있음
		- 2. 메서드가 실행되고, 새로운 문자열이 반환됨
		- 3. 특별한 객체는 파괴되고 원시값 str만 남음
## 숫자형
- 모던 자바스크립트는 숫자를 나타내는 두 가지 자료형을 지원함
- 1. 일반적인 숫자는 배정밀도 부동 소수점 숫자로 알려진 64비트 형식의 IEEE-754에 저장됨
- 2. 임의의 길이를 가진 정수는 BingInt 숫자로 나타낼 수 있음
	- 일반적인 숫자는 2의 53승 이상이거나 -2의 53승 이하일 수 없다는 제약을 두고 있어서 BigInt라는 새로운 자료형이 만들어졌음
- 숫자 옆에 e를 붙이고 그 옆에 개수를 붙여주면 N개의 0을 붙인 것과 같아 숫자를 줄일 수 있음
- 즉, 'e'는 e왼쪽의 수에 e 오른쪽에 있는 수만큼의 10 거듭제곱을 곱하는 효과가 있음
- -e 숫자 를 하면 왼쪽으로 숫자만큼 소수점을 이동한 숫자 표현 가능
- 16진수
	- 0x를 사용해 표현할 수 있음

## 이터러블
- 반복 가능한 객체
- 반복문 for of 를 돌릴 수 있는 자격이 있는 객체
- 어떤 객체가 이터러블이 되려면 반드시 내부에 Symbol.iterator이라는 특별한 메서드를 가지고 있어야 함
- 이터러블인 대표적인 자바스크립트 내장 데이터들
	- 배열(Array)
	- 문자열
	- Map, Set
	- Dom 컬렉션( NodeList, HTMLCollection )
	- arguments 객체
- 일반 객체는 이터러블이 아님
	- 흔히 쓰는 일반 객체 let obj = { a:1, b:2 }는 기본적으로 이터러블이 아님
	- 즉 for of를 직접 돌릴 수 없음
- 이터레이터
	- 실제로 값을 하나씩 꺼내주는 탐색자
	- 이터러블 객체 안에 있는 Symbol.iterator 메서드를 호출하면 튀어나오는 것이 바로 이터레이터 
	- 이터레이터는 현재 어디를 가리키고 있는지 기억하고, 다음 값을 꺼내주는 것
	- 이터레이터 객체는 반드시 next() 메서드를 가지고 있어야 함
- next( )
	- 이를 실행하면 결과물로 { value: 현재 값, done: false }
	- value는 이번에 꺼낸 실제 데이터 값
	- done은 순회가 끝났는지 여부 => false면 아직 남음, true면 끝남
- 둘이 관계와 작동 원리( 한눈에 보기 )
	- 자바스크립트의 for of 문이 내부적으로 동작하는 방식
	- 1. 이터러블에게 순회가능한지 Symbol.iterator 메서드를 요청함
	- 2. 이터러블이 이터레이터 객체를 생성해서 건네줌
	- 3. 순회 루프가 시작되면, 이터레이터의 next( ) 메서드를 반복해서 호출함
	- 4. next( )를 부를 때마다 { value, done }형태의 데이터를 하나씩 받아옴
	- 5. done이 true가 되는 순간, 순회를 자동으로 안전하게 끝냄
- 매번 쓰는 for of구문은 이 과정을 알아서 자동으로 해주고 있었던 것
- let iterator = str [ Symbol.iterator ] ( );

## 맵과 셋
- 맵
	- 키가 있는 데이터를 저장한다는 점에서 객체와 유사하지만 맵은 키에 다양한 자료형을 허용한다는 점에서 차이가 있음
	- 객체는 키에 문자형과 숫자형만 허용
		- 객체는 키를 문자형으로 변환시킴
	- 맵은 키의 타입을 변환시키지 않고 그대로 유지함
	- 전용 메서드
		- set(key, value)
		- get(key)
		- has(key)
		- delete(key)
		- clear( )
		- size
	- 맵은 키로 객체를 허용함
	- 하지만 객체는 그렇지 않음
		- 만약 let john = { name: "john" }
		- let visitsCountObj = { }; // 빈 객체
		- visitsCountObj[ john ] = 123;
		- 이처럼 객체를 키 자리에 넣으면 자바스크립트는 그를 문자열로 강제 변환함
		- 자바스크립트에서 일반 객체를 문자열로 강제 변환하면, 그 결과는 무조건 하나로 고정됨 => "[ object Object ]"
		- 따라서 visitsCountObj["[object Object]"] = 123; 이렇게 받아들임
	- 맵은 삽입 순서를 기억함
		- 맵은 값이 삽입된 순서대로 순회를 실시함
		- 객체가 프로퍼티 순서를 기억하지 못하는 것과 다름
	- Object.entries(obj)
		- 객체를 맵으로 바꾸기
	- Object.fromEntries( map.entries( ) )
		- 맵을 객체로 바꾸기
- 셋
	- 중복을 허용하지 않는 값을 모아놓은 컬렉션
	- 키가 없는 값이 저장됨

		- 셋 만들기
		- 이터러블 객체를 전달받으면(주로 배열을 전달받음) 그 안의 값을 복사해서 셋에 넣어줌

		- 셋 내의 값에 중복이 허용되지 않기 때문
	- set.delete( value )
		- 값을 제거함
		- 호출 시점에 셋 내에 값이 있어서 제거에 성공하면 true, false를 반환함
	- set.has(value)
		- 셋 내에 값이 존재하면 true 아니면 false를 반환함
	- set.clear( )
		- 셋을 비움
	- set.size
		- 셋에 몇 개의 값이 있는지 세어줌
	- for of 나 forEach를 통해 반복 작업 수행가능

## 구조 분해 할당
- 객체와 배열은 자바스크립트에서 가장 많이 쓰이는 자료 구조
- 키를 가진 데이터 여러 개를 하나의 엔티티에 저장할 땐 객체를, 컬렉션에 데이터를 순서대로 저장할 땐 배열을 사용함
- 객체나 배열을 변수로 분해할 수 있게 해주는 것이 구조 분해 할당
- 배열 분해하기
	- let [firstName, surname] = arr;
	- let arr = ["Bora", "Lee"]
	- 이제 인덱스를 이용해 배열에 접근하지 않고도 변수로 이름과 성을 사용할 수 있게 됐음
	- `[`user`.`name`,` user`.`surname`]` `=` "Bora Lee".split(' ');
		- 이처럼 객체 프로퍼티도 좌측에 올 수 있음
- 나머지 패턴 ...
	- 분해하려는 객체의 프로퍼티 개수가 할당하려는 변수의 개수보다 많은 경우
	- 나머지 패턴을 사용하면 배열에서 했던 것처럼 나머지 프로퍼티를 어딘가에 할당하는 게 가능함
	- let options = { title: "Menu", height:200, width:100 }
	- let { title, ...rest } = options;
		- title엔 "Menu", rest엔 { height: 200, width: 100 }이 할당됨
		- alert( rest. height ); // 200
- 중첩 구조 분해
	- 객체나 배열이 다른 객체나 배열을 포함하는 경우, 좀 더 복잡한 패턴을 사용하면 중첩 배열이나 객체의 정보를 추출할 수 있음
- function showMenu( { title = "Menu", width = 100, height = 200 } = { } ) { alert( ${title} ${width} ${height} );}showMenu(); // Menu 100 200
	- 이렇게 매개변수 전체 뒤에 = { }를 붙여주면 인수를 넣지않고 showMenu( )를 호출해도 분해할 대상이 디폴트 값으로 빈 객체가 들어가기 때문에 에러가 나지 않고 위에서 또 설정해둔 디폴트 값으로 할당된다

## 나머지 매개변수와 전개 구문
- 자바스크립트 내장 함수는 인수의 개수에 제약을 두지 않음
- 임의의 (정해지지 않은) 수의 인수를 받는 방법
- 나머지 매개변수 ...
	- 함수를 정의할 땐 인수를 두 개만 받도록 하고, 실제 함수를 호출할 땐 이보다 더 많은 여분의 인수를 전달해도 에러가 발생하지 않음
	- 다만, 반환 값은 처음 두 개의 인수만을 사용함
- ...args
	- 여분의 매개변수는 그 값들을 담을 배열 이름을 마침표 세개 ... 뒤에 붙여주면 함수 선언부에 포함시킬 수 있음
	- 이때 마침표 세 개는 남아있는 매개변수들을 한데 모아 배열에 집어 넣어라 라는 의미
- 앞 부분의 매개변수는 변수로, 남아있는 매개변수들은 배열로 모을 수도 있음
	- 여기서 나머지 매개변수는 항상 마지막에 있어야 함
- arguments 객체
	- 유사 배열 객체인 arguments를 사용하면 인덱스를 사용해 인수에 접근할 수 있음
	- arguments는 이터러블 객체이기 때문에 for(let arg of arguments)를 사용해 인수를 펼칠 수 있음
	- arguments는 유사 배열 객체이면서 이터러블임 그러나 배열은 아니기 때문에 배열 메서드를 사용할 수는 없음
	- arguments는 인수 전체를 담기 때문에 나머지 매개 변수처럼 인수의 일부만 사용할 수 없다는 단점도 있음
- 스프레드 문법
	- 배열 [ 3, 5, 1 ] 이 있고 이 배열을 대상으로 Math.max를 호출하고 싶다고 가정해보자
	- 아무런 조작없이 배열을 있는 그대로 math.max에 넘기면 원하는대로 동작하지 않음
	- Math.max는 배열이 아닌 숫자 목록을 인수로 받기 때문
	- ...를 사용하기 때문에 매개변수와 비슷해보이지만 전개 구문은 나머지 매개변수와 반대 역할
- let arr = [ 3, 5, 1 ];
- Math.max(...arr) 
	- 전개 구문이 배열을 인수 목록으로 바꿔줘 Math.max 계산 가능
- 배열과 객체의 복사본 만들기
	- Object.assign( )을 사용하면 객체를 복사할 수 있었음
	- 스프레드 문법을 사용해도 배열과 객체 복사 가능
## 변수의 유효 범위와 클로저
- 자바스크립트는 함수 지향 언어 => 함수를 동적으로 생성 가능, 생성한 함수를 다른 함수에 인수로 넘길 수 있으며 생성된 곳이 아닌 다른 곳에서 함수를 호출할 수도 있음
- 코드 블록
	- 코드 블록{ ... }안에서 선언한 변수는 블록 안에서만 사용할 수 있음
	- { let message = "안녕하세요"}; 이 밖에서 message를 alert하면 에러
	- 이미 선언된 변수와 동일한 이름을 가진 변수를 별도의 블록 없이 let으로 선언하면 에러가 발생함
	- if, for, while 등에서도 마찬가지로 코드불록 안에서 선언한 변수는 오직 블록 안에서만 접근 가능함
- 중첩함수
	- 함수 내부에서 선언한 함수는 중첩 함수라고 부름
	- function satHi( a, b ){ function getFullName( ){ } }
	- 중첩 함수는 새로운 객체의 프로퍼티 형태나 중첩 함수 그 자체로 반환될 수 있다는 점에서 흥미로움
	- 이렇게 반환된 중첩 함수는 어디서든 호출해 사용할 수 있음
- 렉시컬 함수
	- 1. 변수
		- 렉시컬 환경 객체는 두 부분으로 구성됨
		- 환경 레코드
			- 모든 지역 변수를 프로퍼티로 저장하고 있는 객체
			- this 값과 같은 기타 정보도 여기에 저장됨
		- 외부 렉시컬 환경
			- 외부 코드와 연관됨
		- 변수는 특수 내부 객체인 환경 레코드의 프로퍼티일 뿐
		- 변수를 가져오거나 변경하는 것은 환경 레코드의 프로퍼티를 가져오거나 변경함을 의미함
		- 스크립트 전체와 관련된 렉시컬 환경은 전역 렉시컬 환경이라고 함
			- 전역 렉시컬 환경은 외부 참조를 갖지 않기 때문에 오른쪽을 향하는 화살표가 null을 가리킴
		- 스크립트가 시작되면 스크립트 내에서 선언한 변수 전체가 렉시컬 환경에 올라감
			- 이때 변수의 상태는 uninitialilzed가 됨
			- 자바스크립트 엔진은 이 상태의 변수를 인지하긴 하지만 let을 만나기 전까진 이 변수를 참조할 순 없음
		- 변수가 할당되고 값이 변경되고 순차적으로 진행
	- 2. 함수 선언문
		- 함수는 변수와 마찬가지로 값
		- 다만 함수 선언문으로 선언한 함수는 일반 변수와 달리 바로 초기화됨
		- 함수 선언문으로 선언한 함수는 렉시컬 환경이 만들어지는 즉시 사용할 수 있음
		- 변수가 let을 만나 선언이 될 때까지 사용할 수 없는 것과 다름
		- 그러나 let 변수 = function과 같이 함수를 변수에 할당한 함수 표현식에서는 이렇게 동작하지 않음
	- 3. 내부와 외부 렉시컬 환경
		- 함수를 호출해 실행하면 새로운 렉시컬 환경이 자동으로 만들어짐
		- 함수 호출 중엔 호출 중인 함수를 위한 내부 렉시컬 환경과 내부 렉시컬 환경이 가리키는 외부 렉시컬 환경 총 2개의 렉시컬 환경을 갖게 됨
		- 함수 내부에서 한 변수에 접근할 때 먼저 내부 렉시컬 환경을 살피고 존재하면 그 변수 사용, 없다면 검색 범위를 외부 렉시컬 환경으로 확장해서 찾음
	- 4.함수를 반환하는 함수
		- function makeCounter( ){ let count = 0; return function( ) { return count++; }; } let counter = makeCounter( );
			- makeCounter( )함수가 실행되는 순간 함수 내부 공간에 count라는 변수가 만들어지고 값으로 0이 들어감
			- return function( ) { return count++; };으로 익명함수(이름 없는 함수)를 밖으로 반환
			- let counter = makeCounter( ); 리턴된 그 안쪽 함수가 변수 counter에 담김
			- makeCounter함수는 할 일을 다 끝내고 종료됨
			- counter( )을 실행하면 안쪽의 함수 코드가 실행됨( count++ )
			- 안쪽 함수에는 count라는 변수가 없음
			- 그래서 makeCounter의 공간을 뒤져 count를 찾아 0 반환
			- 동시에 ++ 연산자 때문에 바깥의 count 값은 0에서 1로 증가
			- 

		- makeCounter함수를 호출하면 호출할 때마다 새로운 렉시컬 환경 객체가 만들어지고 여기에 이 함수를 실행하는데 필요한 변수들이 저장됨

## call/ apply와 데코레이터, 포워딩

	- 어떤 함수가 자주 호출된다면 결과를 어딘가에 캐싱해 재연산에 걸리는 시간을 줄이고 싶을 것

## 함수 바인딩
- setTimeout에 메서드를 전달할 때처럼, 객체 메서드를 콜백으로 전달할 때 this 정보가 사라지는 문제가 생김
- 사라진 this
	- 객체 메서드가 객체 내부가 아닌 다른 곳에 전달되어 호출되면 this가 사라짐
	- let user = { name: "철수", sayHi() { alert(`안녕, 나는 ${this.name}야.`); } };
	- 위 상황에서 setTimeout(user.sayHi, 1000);를 하면 안녕 나는 undefined야 가 출력됨
		- setTimeout을 쓰는 순간 자바스크립트는 user라는 객체 통째로 가져가는 게 아니라 sayHi 라는 함수 코드 알맹이만 복사해서 넘겨줌
		- 그렇다면 더 이상 앞에 user이라는 .이 붙어있지 않고 소속을 잃어버린 일반 함수가 되어 버림
		- 자바스크립트에서 객체 소속이 아닌 일반 함수로 실행되면 함수 내부의 this는 객체를 가리키는게 아니라 텅 빈 상태 undefined가 되어 this.name을 찾으려해도 찾을 수가 없게 됨
- 위 문제 해결법
- 방법 1. 래퍼
	- 래퍼 함수 사용하기
	- setTimeout(function( ) { user.sayHi( ); }, 1000 );
	- setTimeout(() => user.sayHi(), 1000);
	- 이런 방식들을 사용하면 this를 기억하게 되므로 문제 해결
- 방법 2. 바인드
	- 모든 함수는 this를 수정하게 해주는 내장 메서드 bind를 제공함
	- let boundFunc = func.bind(context)
	- func.bind(context)는 함수처럼 호출 가능한 특수 객체를 반환
	- 이 객체를 호출하면 this가 context로 고정된 함수 func가 반환됨
	- 따라서 boundFunc를 호출하면 this가 고정된 func를 호출하는 것과 동일한 효과
	- let sayHi = user.sayHi.bind (user); 
- 부분 적용
	- 바인드는 this 뿐만 아니라 인수도 바인딩이 가능함
	- let bound = func.bind(context, [arg1], [arg2], ... );
- 컨텍스트 없는 부분적용
	- 만약 인수 일부는 고정하고 컨텍스트 this는 고정하고 싶지 않은 경우
	- 네이티브 bind만으로는 컨텍스트를 생략하고 인수로 바로 뛰어넘지 못함
	- 이때, 인수만 바인딩해주는 헬퍼 함수 partial을 구현하는 것은 쉬움
	- function partial( func, ...argsBound ) { return function(...args) { return func.call(this, ...argsBound, ...args ) } }
		- ...argsBound는 미리 고정할 인수들
			- partial을 청므 호출할 때 전달하는 인수들
			- 이 인수들은 클로저 덕분에 리턴되는 안쪽 함수 내부에 안전하게 기억됨
		- ...args
			- 나중에 추기로 전달할 인수들
			- 나중에 완성된 함수를 실제로 호출할 때 전달하는 나머지 인수들
		- func.call(this, ...argsBound, ...args)
			- 미리 고정해 둔 인수와 나중에 들어온 인수를 스프레드 연산자로 싹 합쳐 원래 함수에 전달
			- .call을 통해 호출 주체도 보존
## 프로퍼티 플래그와 설명자 
- 프로퍼티 플래그
	- 객체 프로퍼티는 값과 함께 플래그라 불리는 특별한 속성 세 가지를 가짐
- 플래그
	- writable
		- true이면 값을 수정할 수 있음
		- 그렇지 않으면 읽기만 가능함
	- enumerable
		- true이면 반복문을 사용해 나열할 수 있음
		- 그렇지 않으면 반복문을 사용해 나열할 수 없음
	- configurable
		- true이면 프로퍼티 삭제나 플래그 수정이 가능함
		- 그렇지 않다면 불가능
- 평범한 방식으로 프로퍼티를 만들면 해당 프로퍼티의 플래그는 모두 true가 됨
	- 즉 언제든 플래그를 수정할 수 있음
- Object.getOwnPropertyDescription메서드를 사용하면 특정 프로퍼티에 대한 정보를 모두 얻을 수 있음
	- let descriptor = Object.getOwnPropertyDescription(obj, propertyName);
		- obj: 정보를 얻고자 하는 객체
		- propertyName: 정보를 얻고자 하는 객체 내 프로퍼티
	- 메서드를 호출하면 프로퍼티 설명자라고 불리는 객체가 반환되는데, 여기에는 프로퍼티 값과 세 플래그에 대한 정보가 모두 담겨있어야 함
- Object.defineProperty
	- 이를 사용하면 플래그를 변경할 수 있음
	- Object.defineProperty(obj, propertyName, descriptor)
		- obj, propertyName: 설명자를 적용하고 싶은 객체와 프로퍼티
		- descriptor: 적용하고자 하는 프로퍼티 설명자
- Object.defineProperties
	- 이를 사용하면 프로퍼티 여러 개를 한번에 정의할 수 있음
## 프로퍼티 getter와 setter
- 객체의 프로퍼티는 데이터 프로퍼티와 접근자 프로퍼티로 나뉨
- 접근자 프로퍼티의 본질은 함수, 이 함수는 값을 확득하고 설정하는 역할
- 접근자 프로퍼티는 getter와 setter 메서드로 표현됨
- 객체 리터럴 안에서 위 메서드들은 get과 set으로 나타낼 수있음
- let obj = { get propName( ){// getter, obj.propNamed을 실행할 때 실행되는 코드}, set propName(value){ //setter, obj.propName = value를 실행할 때 실행되는 코드 } }
	- getter 메서드는 obj.propName을 사용해 프로퍼티를 읽으려고 할 때 실행되고, setter 메서드는 obj.propName = value으로 프로퍼티에 값을 할당하려 할 때 실행됨
- let user = { name: "John", surname: "Smith", get fullName( ) return `${this,name} ${this.surname}`};, set fullName(value) { [this.name, this.surname] = value.split(" "); };
- user.fullName = "Alice Cooper";
- alert(user.name); //Alice 출력

- 접근자 프로퍼티 설명자
	- 접근자 프로퍼티엔 설명자 value와 writable이 없는 대신 get과 set이라는 함수가 있음
	- get
		- 인수가 없는 함수로 프로퍼티를 읽을 때 동작함
	- set 
		- 인수가 하나인 함수로 프로퍼티에 값을 쓸 때 호출됨
	- enumerable
		- 데이터 프로퍼티와 동일
	- configurable
		- 데이터 프로퍼티와 동일
- 프로퍼티는 접근자 프로퍼티(get/ set 가짐) 또는 데이터 프로퍼티(value가짐) 중 한 종류에만 속하고 둘 다 속할 수 없다는 점을 항상 유의하기
- 한 프로퍼티에 get과 value를 동시에 설정하면 에러가 발생

	- 프로토의 값은 객체나 null만 가능하고 다른 자료형은 무시됨
	- 객체는 두 개의 객체를 상속받지 못함
- 프로토타입은 프로퍼티를 읽을 때만 사용
	- 프로퍼티를 수정, 추가, 지우는 연산은 객체에 직접해야 함
- for in 반복문
	- for in은 상속 프로퍼티도 순회대상에 포함
	- obj.hasOwnProperty(key)를 이용하면 상속 프로퍼티를 순회 대상에서 제외할 수 있음
- obj.hasOwnProperty(key)
	- 이 내장 메서드는 key에 대응하는 프로퍼티가 상속 프로퍼티가 아니고 obj에 직접 구현되어 있는 프로퍼티일 때만 true를 반환함
## 함수의 prototype 프로퍼티
- 생성자 함수( new F( ))로 객체를 만들었을 때 리터럴 방식과 다른 점은 생성자 함수의 프로토타입이 객체인 경우 new연산자를 사용해 만든 객체는 생성자 함수의 프로토타입 정보를 사용해 [ [ prototoype ] ]을 설정한다는 것
- let animal = { eats: true };
- function Rabbit(name) {this.name = name};
- Rabbit.prototype = animal;
	- 앞으로 new Rabbit을 통해 만들어질 모든 객체의 부모 ([ [ prototoype ] ])를 animal 객체로 설정하겠다는 의미
- let rabbit = new Rabbit("흰 토끼");
- 그러나 이미 만들어진 객체에 Rabbit.prototype = animal; 를 사용해도 적용되지 않음
- delete 연산은 객체에 직접 적용됨
	- delete rabbit.eats는 rabbit에서 eats 프로퍼티를 제거하는데 `let` rabbit `=` `new` `Rabbit``(``)``;` 이렇게 상속받았다해도 rabbit에는 eat이 없기 때문에 아무일도 일어나지 않음
## 내장 객체의 프로토타입
- 프로토타입 프로퍼티는 자바스크립트 내부에서도 광범위하게 사용됨
- 모든 내장 생성자 함수에서 prototype 프로퍼티를 사용함
- Object.prototype
	- new Object()를 호출하거나 리터럴 문법 `{...}`을 사용해 객체를 만들 때, 새롭게 생성된 객체의 `[[Prototype]]`은 바로 앞 챕터에서 언급한 규칙에 따라 Object.prototype을 참조
	- 따라서 `obj.toString()`을 호출하면 `Object.prototype`에서 해당 메서드를 가져옴
- 다양한 내장 객체의 프로토타입
	- 배열을 만들면 new Array( )의 디폴트 생성자가 내부에서 동작하여 Array.prototype이 배열의 프로토타입이 되고 배열 메서드를 사용할 수 있게됨
	- 모든 내장 프로토타입의 상속 트리 꼭대기에는 Object.prototype이 있음
	- 이 외에도 함수는 Function.prototype에서 받아옴
- 원시값
	- 원시값은 객체가 아님 
	- 이런 원시타입(문자열 숫자, 불린값 등) 값의 프로퍼티에 접근하려고 하면 내장 생성자 String, Number,Boolean을 사용하는 임시 래퍼 객체가 생성됨
	- 임시 래퍼 객체는 이런 메서드를 제공하고 난 뒤 사라짐
- 프로토타입 불러오기
	- 유사 배열 객체를 만들고 여기에 Array메서드를 복사
	- obj.join = Array.prototype.join;
- 원시프로토타입 수정하기
	- Function.prototype.defer = function(ms) { setTimeout( this, ms ); }; function f( ){ alert ( "Hello!" ); } f.defer(1000);
## 프로토타입 메서드와 __ proto __가 없는 객체
- __ proto __ 는 다소 구식이기 때문에 사용하지 않는 것이 좋음
- 대신 모던한 메서드 사용하기
	- Object.create(proto, [ descriptors ]) 
		- `[[Prototype]]`이 `proto`를 참조하는 빈 객체를 만듦
	- Object.getPrototypeOf(obj)
		- obj의 `[[Prototype]]`을 반환
	- Object.setPrototypeOf(obj, proto)
		- obj의 `[[Prototype]]`이 proto가 되도록 설정
- `let` obj `=` Object`.``create``(``null``)``;
	- 이렇게 객체를 만들면 __ proto __ getter와 setter을 상속받지 않음
	- 이제 __ proto __ 는 평범한 데이터 프로퍼티처럼 처리됨
	- 이렇게 프로토타입이 없는 빈 객체는 아주 단순한 혹은 순수 사전식 객체라고 부름
	- 일반 객체보다 훨씬 단순함
	- 아주 단순한 객체는 내장 메서드가 없다는 단점이 있음
- ```javascript
function Rabbit(name) {
  this.name = name;
}
Rabbit.prototype.sayHi = function() {
  alert(this.name);
};

let rabbit = new Rabbit("Rabbit");
```

- `rabbit.prototype.sayHi = ...` 코드는 `Rabbit`의 부모 공간에 `sayHi`라는 공유 메서드를 등록해 둔 것
- let rabbit = new Rabbit("Rabbit")
	- 이렇게 생성자 함수를 실행하면 (`[[Prototype]]`)가 생성자 함수의 부모 공간인 `Rabbit.prototype`을 가리키도록 설정
	- Rabbit 내부의 this가 방금 만든 빈 객체를 가리키도록 바인딩됨
	- 함수 코드가 실행됨
- 생성자 함수로 만든 rabbit 객체는 자기 자신의 고유 속성 name:"Rabbit"을 가지면서도 부모 연결고리를 통해 공통 메서드 sayHi를 호출할 수 있게 됨

```javascript
rabbit.sayHi();
Rabbit.prototype.sayHi();
Object.getPrototypeOf(rabbit).sayHi();
rabbit.__proto__.sayHi();
```

- rabbit.sayHi( )
	- this는 점 좌측에 있는 객체를 기준으로 바인딩되므로
	- this는 rabbit
	- rabbit은 name 프로퍼티 Rabbit 존재
	- 정상적으로 출력
- Rabbit.prototype.sayHi();
	- this $\rightarrow$ Rabbit.prototype
	- `Rabbit.prototype`에 들어있는 것은 오직 `sayHi` 함수뿐이며, `name` 프로퍼티는 정의되어 있지 않음
	- undefined 출력
- Object.getPrototypeOf(rabbit).sayHi();
	- this $\rightarrow$ Rabbit.prototype
	- 마찬가지로 undefined 출력
- rabbit.__proto__.sayHi();
	- 이거 역시 마찬가지
