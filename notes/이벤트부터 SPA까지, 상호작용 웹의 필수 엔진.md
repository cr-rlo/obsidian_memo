## 이벤트는 왜 필요한가
- 이벤트 처리 주기
	- 반응 발생
	- 이벤트 발생
	- 이벤트 리스너 활성화
	- 이벤트 핸들러 실행
- 이벤트 처리 시퀀스
	- 이벤트 발생
	- 이벤트 핸들러 정의
		- 이벤트 핸들러: 실제로 실행되는 함수(코드 덩어리)
	- 이벤트 리스너 연결: 이벤트 + 핸들러
		- 이벤트 리스너: 신호를 듣는 장치
	- 이벤트 핸들러 실행
- 이벤트가 없다면?
	- 모든 요소는 정적인 상태에 머무름
	- 단지 선택하고 값을 바꾸는 수준에 머무름
- 지금의 웹은 -  상호작용 중심의 UI 시대
	- 현대 웹의 특징
		- 유저 행동에 따라 즉시 반응
		- 상황에 따라 UI가 동적으로 변화
		- 실시간 피드백과 풍부한 인터랙션이 기본
- 이벤트는 정적인 HTML을 살아있는 UI로 바꿔주는 핵심 도구
- 이벤트의 핵심 = 특정 순간에 특정 함수 실행
	- 이벤트란 결국 정해진 상황에 함수를 실행하는 일
	- 콜백 함수가 중심 개념
## 콜백 함수란 무엇인가
- 콜백함수는 특정 타이밍에 실행되도록 등록해두는 함수
- 우리가 직접 호출하지 않고, 다른 코드가 대신 호출해주는 함수
- 즉 eventListener에 등록된 함수
- 이벤트 리스너와 콜백 함수 - 연결의 핵심
	- ex) button.addEventListener( "click", function( ){ } );
	- click 이벤트가 발생하면 브라우저가 익명함수( callback function )을 자동 실행함
	- 조건이 충족되면 외부에서 호출되는 함수
- 함수이름 VS 함수실행: 헷갈리지 말아야 할 차이
	- button.addEventListener( "click", sayHello );
		- sayHello 함수 자체를 전달(콜백 등록)
		- 브라우저가 클릭 시점에 실행
	- button.addEventListener( "click", sayHello( ) );
		- sayHello 함수를 즉시 실행하고 그 결과값을 이벤트리스너에 전달
		- 실제로는 클릭과 상관없이 실행되어버림
		- 등록 시 바로 실행, 클릭 시(이벤트) 반응 없음
- 인자를 넘겨야 할 땐, 익명 함수로 감싸기(혹은 화살표 함수)
	- button.addEventListener( "click", function( ){ sayHello("민지") } );
	- button.addEventListener( "click", ( ) => { sayHello("민지") } );
	- 콜백 함수에 인자가 필요할 땐, 익명함수나 화살표 함수로 감싸야 이벤트 발생 시점에 정확히 실행됨
- 이벤트 리스너에서 어떤 요소가 함께 작동해야 하는가?
	- 이벤트와 콜백 함수는 반드시 함께 작동해야 함
	- 이벤트(조건): 사용자 행동을 트리거
		- 언제 실행할지를 결정
	- 콜백 함수(반응): 사용자 행동에 반응
		- 무엇을 실행할지를 정의
