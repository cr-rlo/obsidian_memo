## 이벤트는 왜 필요한가
- 이벤트 처리 주기
	- 반응 발생
	- 이벤트 발생
	- 이벤트 리스너 활성화
	- 이벤트 핸들러 실행
- 이벤트 처리 시퀀스
	- 이벤트 발생
	- 이벤트 핸들러 정의
		- 이벤트 핸들러: 실제로 실행되는 함수(코드 덩어리)
	- 이벤트 리스너 연결: 이벤트 + 핸들러
		- 이벤트 리스너: 신호를 듣는 장치
	- 이벤트 핸들러 실행
- 이벤트가 없다면?
	- 모든 요소는 정적인 상태에 머무름
	- 단지 선택하고 값을 바꾸는 수준에 머무름
- 지금의 웹은 -  상호작용 중심의 UI 시대
	- 현대 웹의 특징
		- 유저 행동에 따라 즉시 반응
		- 상황에 따라 UI가 동적으로 변화
		- 실시간 피드백과 풍부한 인터랙션이 기본
- 이벤트는 정적인 HTML을 살아있는 UI로 바꿔주는 핵심 도구
- 이벤트의 핵심 = 특정 순간에 특정 함수 실행
	- 이벤트란 결국 정해진 상황에 함수를 실행하는 일
	- 콜백 함수가 중심 개념
## 콜백 함수란 무엇인가
- 콜백함수는 특정 타이밍에 실행되도록 등록해두는 함수
- 우리가 직접 호출하지 않고, 다른 코드가 대신 호출해주는 함수
- 즉 eventListener에 등록된 함수
- 이벤트 리스너와 콜백 함수 - 연결의 핵심
	- ex) button.addEventListener( "click", function( ){ } );
	- click 이벤트가 발생하면 브라우저가 익명함수( callback function )을 자동 실행함
	- 조건이 충족되면 외부에서 호출되는 함수
- 함수이름 VS 함수실행: 헷갈리지 말아야 할 차이
	- button.addEventListener( "click", sayHello );
		- sayHello 함수 자체를 전달(콜백 등록)
		- 브라우저가 클릭 시점에 실행
	- button.addEventListener( "click", sayHello( ) );
		- sayHello 함수를 즉시 실행하고 그 결과값을 이벤트리스너에 전달
		- 실제로는 클릭과 상관없이 실행되어버림
		- 등록 시 바로 실행, 클릭 시(이벤트) 반응 없음
- 인자를 넘겨야 할 땐, 익명 함수로 감싸기(혹은 화살표 함수)
	- button.addEventListener( "click", function( ){ sayHello("민지") } );
	- button.addEventListener( "click", ( ) => { sayHello("민지") } );
	- 콜백 함수에 인자가 필요할 땐, 익명함수나 화살표 함수로 감싸야 이벤트 발생 시점에 정확히 실행됨
- 이벤트 리스너에서 어떤 요소가 함께 작동해야 하는가?
	- 이벤트와 콜백 함수는 반드시 함께 작동해야 함
	- 이벤트(조건): 사용자 행동을 트리거
		- 언제 실행할지를 결정
	- 콜백 함수(반응): 사용자 행동에 반응
		- 무엇을 실행할지를 정의
## 이벤트 리스너와 핸들러, 정확히 무엇이 다를까
- 이벤트 리스너
	- 어떤 일이 생기면 알려줘라고 감지 장치를 등록하는 행위
- 이벤트 핸들러
	- 실제로 이벤트가 발생했을 때 실행될 콜백 함수(반응 동작)
- button.addEventListener( "click", function( ){ } );
	- 여기서 addEventListener은 이벤트 리스너 등록 메서드
	- click은 클릭이라는 이벤트 종류 등록, 즉 조건
	- function()은 이벤트 핸들러, 즉 실제로 실행될 동작 (콜백 함수)
	- 이때 첫 번째 인자로 전달되는 이벤트 종류 문자열은 정해진 약속, 임의로 바꿀 수 없음
		- click, input, keydown, submit, mouseover .....
	- 두 번째 인자인 이벤트 핸들러는 개발자가 유연하게 작성할 수 있음
- 이벤트 리스너 함수와 이벤트 핸들러 함수를 분리해서 정의하면 가독성이 향상되고 유지보수가 편리함 심지어 여러 리스너가 하나의 핸들러를 공유할 수도 있음
## 인라인 이벤트 리스너 - 가장 오래된 방식의 진화와 한계
- 인라인 이벤트 리스너 
	- < button onclick = "alert('클릭되었습니다!')" >클릭< /button >
	- HTML 태그 내부에 직접 이벤트를 등록하는 오래된 방식이며, 실무에서는 잘 사용하지 않으며 단점도 많음
		- 여기서 onclick 속성이 바로 인라인 이벤트 리스너이며, 속성 값으로 자바스크립트 코드가 직접 들어가 클릭 시 실행될 코드를 브라우저가 내부적으로 등록함
		- HTML만 봐도 어떤 이벤트가 연결되었는지 직관적으로 알 수 있어 편리하지만, 자바스크립트를 분리하지 않기 때문에 유지보수에 취약한 구조
	- 인라인 이벤트 리스너는 HTML과 자바스크립트가 한 곳에 뒤섞이는 방식
		- 구조(HTML)와 동작(javascript)의 역할 구분이 모호해지며, 규모가 커질수록 코드를 파악하고 수정하기 어려움
		- 또한, 복잡한 조건문, 반복문, 함수 호출 등을 담기 어려움
		- 단순한 알림 정도는 가능하지만, 복잡한 로직은 결국 외부 스크립트로 분리해야 하며, 그렇다면 처음부터 자바스크립트로 리스너를 등록하는 방식이 더 적절할 것
		- 인라인 이벤트 리스너는 개발자 도구에서 함수명이 아닌 문자열로 표시되기 때문에, 이벤트 연결을 추적하거나 함수 호출 흐름을 파악하기 어려워 디버깅과 버그 수정에 더 많은 시간이 소모될 수 있음
## 인라인 프로퍼티 방식 - 코드 안에서 직접 이벤트를 다루는 두 번째 방법
- const button = document.querySelector("button");
- button.onclick = function ( ){ alert("버튼이 클릭되었습니다!"); };
	- 자바스크립트 코드 안에서 요소의 속성처럼 이벤트를 등록하는 방식
	- 이벤트를 HTML 태그에 직접 쓰는 것이 아니라, 자바스크립트에서 연결
- 덕분에 HTML 구조는 순수하게 유지되며, 자바스크립트에서 동적으로 이벤트를 연결할 수 있음
- 인라인 리스너보다는 더 구조적인 접근이 가능하고 관심사 분리에도 도움이 되는 방식
- 이 방식도 onclick이라는 속성에 함수를 대입하는 구조이기 때문에, 하나의 핸들러만 등록가능하다는 제약이 있음
	- 여러 개의 클릭 핸들러를 동시에 연결할 수 없으며, 마지막에 등록된 하나의 함수만 실행됨
	- 만약 여러 개의 핸들러를 등록한다면 첫 번째 핸들러는 사라지고 두 번째 핸들러만 동작함
	- 때문에 코드 예측성과 디버깅에 혼란을 줄 수 있기 때문에 여러 이벤트 핸들러를 함께 관리해야 하는 상황에서는 더 이상 적합하지 않은 방식
- 이 방식은 브라우저가 미리 약속한 이벤트 속성명을 사용해야 함
	- onclick, onmouseover, onkeydown 등은 HTML 표준에 의해 예약된 이름이며, 개발자가 임의로 바꿀 수 없음
	- 즉, 이벤트 종류는 DOM이 정한 정확한 이름을 따라야 하며, 그 속성에 들어가는 함수(콜백)은 개발자가 자유롭게 정의할 수 있음
## 세 가지 이벤트 연결 방식 총정리 - 실무에서 쓰는 주 방식
- 인라인 이벤트 리스너
	- HTML과 자바스크립트가 한 곳에 뒤섞이는 방식
	- 구조와 동작의 역할 구분이 모호해지며 규모가 커질수록 코드를 파악하고 수정하기 어려워짐
- 인라인 프로퍼티 방식
	- 자바스크립트의 코드 안에서 DOM요소의 이벤트 속성에 함수를 직접 할당하는 형태
	- HTML 구조는 순수하게 유지되며, 자바스크립트에서 동적으로 이벤트를 연결할 수 있음
	- 인라인 리스너보다는 구조적인 접근이 가능하고 관심사 분리에도 도움
	- 하지만 이벤트 리스너를 하나만 등록할 수 있다는 치명적인 단점
- 이벤트 리스너와 콜백함수 방식
	- addEventListener() 메서드 사용
	- 위와 같이 작성하면 버튼 클릭 시 여러 개의 핸들러가 순서대로 실행됨
	- 이처럼 이벤트를 겹쳐서 등록할 수 있다는 점은 복잡한 UI를 가진 실제 웹 서비스에서 매우 유리한 구조
	- 또한 removeEventListener을 통해 특정 핸들러만 제거할 수 있고, 이벤트 전파를 제어하기 위한 옵션도 함께 제공됨
## 가장 유연한 방식 - addEventListener
- addEventListener( "이벤트 이름", 콜백함수 ); 는 DOM요소에 이벤트 발생 시 실행할 콜백 함수를 등록하는 메서드
- 이벤트가 실제로 발생했을 때, 브라우저가 미리 우리가 등록해둔 콜백함수를 호출
- 이 함수는 즉시 실행되지 않고 이벤트 발생 시에만 호출된다는 점이, 바로 콜백함수의 본질
- 이벤트 이름은 반드시 문자열로 작성해야 하며, DOM에서 미리 약속된 이름만 사용할 수 있음
	- click, keydown 등...
- 두 번째 인자는 우리가 작성한 콜백 함수
	- 이벤트 발생 시 브라우저가 자동으로 호출
- 하나의 요소에 여러 개의 리스너를 동시에 등록할 수 있음
	- 순서대로 실행되며, 서로 덮어쓰지 않음
- this 키워드의 동작 차이 - 일반함수 vs 화살표 함수
	- 일반 함수에서는 this가 이벤트가 발생한 요소 자신을 가리키고, 화살표 함수에서는 상위 스코프의 this(window 등)을 그대로 사용함
- 이벤트 위임(event delegatiion), 이벤트 제거(removeEventListener), 이벤트 전파 제어(capture/bubble phase)등 고급 기능까지 폭 넓게 지원
- 웹 UI 전체의 구조와 동작을 유연하게 통제
## 이벤트 객체와 this, 그리고 event.target
- 이벤트 객체
	- addEventListener()에 콜백 함수를 넘길 때, 그 콜백 함수의 첫 번째 매개변수 자리는 어떤 이름이든 지정할 수 있음
	- 하지만 중요한 것은 이름이 아니라, 브라우저가 이벤트가 발생할 때마다 자동으로 하나의 객체를 콜백함수에 전달한다는 것 -> 이벤트 객체
	- 콜백함수의 첫 번째 인자로 전달되는 이벤트 객체는 개발자가 직접 호출하는 것이 아니라 브라우저가 이벤트 발생 시점에 자동으로 넣어주는 정보 객체라는 것
	- 이벤트 객체의 이름으로 무엇이든 쓸 수 있지만 관례적으로 e, event, obj 권장
- event.target
	- 이벤트 객체 안에서 가장 자주 사용하는 속성 중 하나
	- 이벤트가 발생한 진짜 대상
	- 여러 개의 버튼이나 요소가 있을 때, 하나하나를 직접 선택하지 않고도 event.target을 통해 클릭된 요소를 바로 참조할 수 있음
- this - 일반 함수에서의 동작
	- 일반함수 function 안에서의 this는 이벤트를 등록한 DOM 요소 자체를 가리킴
	- 예를 들어 button.addEventListener("click", function( ){ console.log(this); }) 
	- 이 코드에서 this는 addEventListener로 이벤트를 등록한 그 버튼 요소 자신을 참조 
	- 즉, 콜백 함수 안에서 this를 사용하면 해당 DOM 요소에 직접 접근할 수 있게됨
- this - 화살표 함수 안에서의 동작 -> 외부 스코프를 따른다
	- 화살표 함수에서는 this의 동작 방식이 일반 함수와 다름
	- 화살표 함수는 자신이 선언된 시점의 외부 스코프에서 this를 가져오기 때문에 window 또는 상위 렉시컬 스코프를 따라감
	- button.addEventListener("click", ( ) => { console.log(this); });
- 이 차이는 매우 중요하기 때문에 이벤트 핸들러 내부에서 this를 사용할 계획이 있다면 반드시 function(){}형태의 일반 함수를 사용해야 함
- 그렇다면 this 대신 event.target을 쓰는 이유
	- this는 이벤트를 등록한 대상
		- 리스너를 붙인 요소
	- event.target은 이벤트가 발생한 대상
		- 사용자의 액션이 닿은 곳
	- 예를 들어 < ul >에만 클릭 이벤트를 등록하고, 어떤 < li >가 클릭되었는지 구분하고 싶을 때 this는 항상 이벤트를 등록한 상위 요소인 < ul >, event.target은 클릭된 실제 < li > 요소나 그 안의 자식 요소를 가리킴
