## 자료 구조와 알고리즘
- 자료구조
	- 데이터가 어떤 구조로 저장되고 어떻게 사용되는지 나타냄
	- 가장 단순한 자료구조는 변수
	- 배열도 자료구조
	- 자료구조에 따라 처리 방법이 달라짐
- 알고리즘
	- 어떤 문제를 해결하기 위한 확실한 방법
	- 모호한 방식은 알고리즘이라고 부를 수 없음
	- 자료구조에 따라서 알고리즘이 달라짐
	- 알고리즘을 동시에 사용할 수는 없음 -> 최적의 방법을 선택하기

## 시간 복잡도
- 더 좋은 알고리즘이란 사용자의 요구에 따라 다름
- 시간복잡도란 특정 알고리즘이 어떤 문제를 해결하는 데 걸리는 시간
- 코드에서 성능에 많은 영향을 주는 부분은 반복문
- 반복문이 여러 번 반복될수록 실행시간이 길어짐
- 성능을 평가할 때 반복문을 보고 평가
- 빅 오 표기법
	- 성능의 최악의 경우를 평가
	- 선형 시간 알고리즘
	- 입력이 늘어날 때 계산량이 늘어나는 척도를 나타내기 위한 것
	- 계산에 가장 많은 영향을 미치는 항만 표기
	- ex) 3n* n + 100n => O(3n * n)

## 배열
- 모든 프로그래밍 언어에서 기본적으로 제공하는 자료구조
- 일반적인 배열
	- 일반적으로 프로그래밍 언어에서는 배열을 선언할 때 배열의 크기를 알려줌
	- 배열을 선언했다면 운영체제는 메모리에서 그만큼의 숫자가 들어갈 수 있는 연속된 빈 공간을 찾아서 순서대로 할당함
	- 할당하지 않은 부분에는 의미 없는 값이 저장
	- 운영체제는 배열의 시작 주소만 기억
	- 인덱스를 이용해 특정 값에 한 번에 접근
	- 배열의 인덱스 참조는 길이에 상관없이 한번에 가져오기 때문에 O(1)의 성능
	- 따라서 배열은 읽기/쓰기 즉, 참조에서 좋은 성능을 보임
	- 그러나 데이터의 삽입, 삭제의 성능은 좋지 않음
	- 처음 할당한 공간보다 배열의 크기를 넘어서 할당하면 문제 발생
	- 운영체제는 처음에 사용자에게 특정 크기만큼의 메모리 공간을 요청 받았고 연속된 공간을 할당 
	- 배열의 끝에는 중요한 데이터가 있을 수도 있기 때문에 마음대로 확장할 수 도 없음
	- 따라서 처음 공간보다 더 넓은 값의 배열을 다시 찾아서 할당해야 함
	- 심지어 기존 데이터를 새로 할당하는 공간에 다시 복사까지 해야 함
	- 그렇다고 애초에 이런 일이 발생하지 않도록 처음부터 큰 공간을 할당하면 메모리 낭비와 배열 내부에서도 공간 낭비 문제가 발생함
- 자바스크립트 배열
	- 처음부터 배열의 크기를 지정하지 않음
	- push, pop 함수로 데이터 추가, 제거가 가능함
	- 자바스크립트에서 배열은 상황에 따라서 연속적으로 할당하지만, 대부분은 불연속적으로 메모리 할당
	- 불연속적으로 할당된 메모리는 내부적으로 연결해서 사용자에게는 배열인 것처럼 보임
- 배열의 장점
	- 읽기와 쓰기와 같은 참조에는 좋은 성능을 보임
- 배열의 단점
	- 크기 예측이 힘들기 때문에 메모리 낭비가 발생할 수 있음
	- 데이터의 삽입, 삭제가 비효율적임
	- 단점을 해결하기 위해 저장하려는 데이터들을 메모리 공간에 분산해 할당하고 이들을 연결 -> 노드라는 것을 만들어서 수행
- 노드의 구조
	- 데이터를 담는 변수 하나와 다음 노드를 가르키는 변수 하나 가짐
	- 데이터가 필요하다면 필요한 데이터만큼 노드를 만들어 데이터를 저장하고 다른 노드를 가리켜 연결 -> 연결리스트라고 부름
## 연결리스트 
- 개념
	- 연결리스트는 첫 노드의 주소만 알고 있으면 다른 모든 노드에 접근할 수 있음
	- 연결이라는 특성 때문에 배열과는 다른 장단점
- 장점
	- 연결리스트에서 데이터를 추가한다면 빈 메모리 공간 아무 곳에 데이터를 생성하고 연결만 해주면 되기 때문에 배열에서 초기 크기를 알아야 한다는 단점 적용 x
	- 배열에서는 중간에 데이터를 삽입하면 그 뒤에있는 데이터들은 모두 뒤로 밀려나기 때문에 오버헤드가 많이 들지만 연결리스트는 다음 가리키는 노드만 바꿔주면 되기 때문에 간단
- 단점
	- 배열은 메모리에 연속된 공간에 할당되어 있어서 시작주소만 알면 뒤에 있는 데이터 접근이 쉬움
	- 연결리스트는 데이터들이 전부 떨어져있어서 바로 접근할 수 없음
	- 첫 번째 노드에서 찾아가는 방식
	- 연결리스트에서 데이터 참조는 O(n)의 성능
- 배열과 연결리스트 비교
	- 배열은 크기 고정 / 연결리스트는 필요할 때마다 노드를 만들어 연결해주기 때문에 동적
	- 배열은 메모리에 연속된 공간에 할당 / 연결리스트는 메모리에서 힙 영역이라는 곳에 런타임에 불연속적인 빈 공간에 할당
	- 배열은 메모리 접근이 굉장히 빠름 / 연결리스트는 데이터 참조를 위해 앞에서부터 해당 노드까지 접근해야해서 느림
	- 배열에서 데이터를 삽입하려면 기존 모든 데이터를 옮겨야해서 O(n)의 성능 / 연결리스트는 삽입하려는 노드까지 노드를 계속 타고 들어가야 하니 마찬가지로 O(n)

- 어떤 프로그램을 만드는데 데이터의 수가 자주 바뀌지 않고 참조가 자주 일어난다면 배열, 데이터의 삽입과 삭제가 자주 일어나 데이터의 수가 자주 바귄다면 연결리스트

- 추상자료형
	- 어떠한 데이터와 그 데이터에 대한 연산을 표기하는 것
	- 기능만 나열, 구체적인 구현 방법은 나오지 않은 것
- 연결리스트의 추상 자료형(자바스크립트에서 구현)
	- 데이터는 정수라고 가정
	- 연결리스트에서 필요한 연산
		- 연결리스트의 모든 원소를 출력하는 기능
			- printAll()
		- 연결리스트의 모든 원소를 제거하는 기능
			- clear()
		- 원하는 인덱스에 데이터를 삽입하는 기능
			- insertAt(index, data);
		- 마지막 데이터 뒤에 데이터를 삽입하는 기능
			- insertLast(data);
		- 원하는 인덱스의 데이터를 제거하는 기능
			- deleteAt(index);
		- 마지막 데이터를 제거하는 기능
			- deleteLast();
		- 원하는 인덱스를 읽는 기능
			- getNodeAt(index);
- 연결리스트는 데이터를 담은 노드를 서로 연결하는 구조
- 이를 위해 가장 먼저 노드 만들기 -> 노드 클래스 선언, 클래스를 인스턴스화 했을 때 자동으로 호출되는 생성자를 만듦, 생성자에서 초기화
- 생성자의 매개변수로 data와 next만들기 -> next는 기본값 null
- 매개변수 data는 필수지만 next는 입력하지 않는다면 null이 할당
- 자바스크립트에서 클래스 내의 변수를 프로퍼티라고 함
- 생성자 내에서 data와 next 프로퍼티를 만들어 매개변수 data와 next로 초기화
- 다른 자바스크립트 파일에서 node 클래스를 참조할 수 있도록 export

- 다음으로 LinkedList 클래스 선언 
- 생성자를 만드는데 매개변수는 필요없고 총 저장된 노드의 수를 저장하는 count 프로퍼티를 만들어 0으로 초기화 해줌
- insertAt 함수 만들기
	- 원하는 인덱스에 데이터 삽입
	- 삽입할 위치를 뜻하는 index와 삽입할 데이터를 뜻하는 data 매개변수를 만들어줌

	### insertAt(index, data){}
	- 함수 본문에서는 가장 먼저 예외처리를 해줌
	- 연결리스트의 크기보다 큰 곳에 삽입하거나 음수위치에 삽입하는 경우 에러를 발생시킴
		- if(index > this.count || index <0){ throw new Error("범위를 넘어갔습니다.");}
	- 새로 삽입할 노드 생성 
		- 매개변수 data를 node의 생성자로 넘겨줘서 node의 data를 설정
		- 두 가지 상황을 나누는 코드
			- 리스트 가장 앞에 삽입해서 새로 삽입하는 노드가 head가 되는 경우
				- if(index == 0)
					- 새로 생성한 노드의 next를 head를 가르키게 함
					- 새로 생성한 노드를 head로 변경
			- 그 외
				- else
				- 원하는 인덱스까지 노드를 타고 들어가서 새로 삽입하는 경우
				- 만약 index 3에 삽입한다면 head 노드에서 세 번째 떨어진 노드에 삽입하는 경우라고 생각하면 됨
				- currentNode로 세 번째 떨어진 노드 전까지 이동하고 newNode가 currentNode가 가리키던 노드, 즉 세 번째 노드를 가리키게 함
				- 그리고 currentNode가 새로운 노드(data)를 가리키게 하면 끝남

				- 먼저 삽입하려믄 노드 바로 전까지 가기 위한 변수 생성
				- let currentNode = this.head; -> head에서 시작하기 때문에 head로 초기화
				- 목표 index 전까지 next를 이용해 currentNode 이동
				- 새로운 노드가 currentNode의 next노드를 가리키고 currentNode가 새로운 노드를 가리키면 됨
	### printAll()
	- 연결리스트의 모든 원소 출력
	- currentNode가 head를 가리키도록 초기화
	- 리스트의 끝가지 순회하며 출력
	- currentNode가 null이 될 때까지 계속 next 노드를 참조해주면 됨
	### clear()
	- 연결리스트의 모든 원소를 제거하는 기능
	- head가 null 을 가리키게 해서 참조하는 것이 없게 만들어주고 count를 0으로 만들어주면 리스트는 비워짐
	### inserLast()
	- 마지막 데이터 뒤에 삽입하는 기능
	- insertAt함수를 이용하면 쉽게 구현 가능
	- insertLast(data){}
	- 함수 내에서 insertAt(index, data) 함수를 호출해서 index에 리스트의 크기인 count를 넣어 가장 뒤에 데이터 삽입
	### deleteAt(index)
	- 원하는 인덱스의 데이터를 제거하는 기능
	- 매개변수로 index만 받으면 제거할 수 있으므로 data는 필요없음
	- insertAt함수와 마찬가지로 에러처리 -> 리스트의 크기를 넘어서면 에러 발생
	- 노드를 순회할 변수 currentNode 만들기 -> this.head로 초기화
	- 두 가지 상황 나누기
		- 첫 번째 상황은 head 노드, 즉 첫 번째 노드를 제거하는 상황
			- if(index == 0)
			- 삭제된 노드를 리턴하기 위해 삭제될 노드를 저장 -> let deleteNode = this.head
			- 그리고 head를 head의 next노드로 설정
			- 삭제 됐으니 count도 하나 줄여줌
			- 삭제된 노드는 return deletedNode로 리턴
		- 두 번째는 첫 번째 노드를 제외한 나머지 노드를 제거하는 상황
			- else
			- for문으로 제거할 노드 이전 노드까지 순회
			- 제거할 노드는 반환되어야 하므로 변수에 저장
			- 제거할 노드의 이전 노드가 제거할 노드의 next노드를 가리키게 해줌
			- 삭제했으니 count를 하나 줄여주고 삭제된 노드 리턴
	### deleteLast()
	- 마지막 데이터를 제거하는 기능
	- deleteLast()함수를 선언하고 deleteAt()함수 호출하는데 index는 리스트의 카운트보다 1작은 값 넘겨줌
	- return this.deleteAt(this.count - 1)
	### getNodeAt()
	- 원하는 인덱스를 읽는 기능
	- 함수를 선언하고 매개변수는 읽으려는 index넘겨줌
	- getNodeAt(index){}
	- 읽고자 하는 인덱스가 리스트 범위를 넘어갈 때 에러 발생
	- 리스트를 순회할 currentNode 변수를 만들고 head와 같은 노드를 가리키게 함
	- for 문을 통해서 currentNode가 해당 인덱스까지 순회
	- 마지막으로 currentNode를 리턴해주면 끝


## 스택
- FILO 규칙
	- 먼저 들어간 데이터가 나중에 쓰이는 규칙을 따르는 데이터 구조 스택
	- 설거지하며 쌓아가는 접시탑을 생각해봐
- 위 규칙만 따른다면 어떤 자료구조로 구현하든 상관 없음
- 이전에 배운 자료구조인 배열과 연결리스트 각각으로 스택 구현 가능
- 연결리스트는 헤드 하나를 가지고 모든 노드를 연결
- 헤드를 이용하면 스택을 아주 간단하게 구현 가능
	- 데이터 삽입을 무조건 첫 번째 인덱스에 하는 것
	- 데이터 제거도 무조건 첫 번째 인덱스에 하는 것
	- 한쪽으로만 데이터를 삽입, 제거하면 간단하게 스택이 됨
- 포토샵이나 그림판으로 그림을 그릴 때 실수하면 되돌리기 기능
- 컴퓨터는 이 작업들을 모두 스택에 기록하고 있는 것

- 스택의 추상자료형
	- 데이터 삽입
		- push
	- 데이터 제거(꺼내기)
		- pop
	- top에 있는 데이터 참조
		- peek
	- 비었는지 체크
		- isEmpty

- 스택을 이전에 만들었던 연결리스트로 만들 예정이기 때문에 만들어뒀던 연결리스트 import

## 큐 
- FIFO 규칙
	- 먼저 들어간 데이터가 먼저 나오는 규칙
	- 마트에서 계산대 줄에서 계산하는 걸 생각해보자
	- 큐는 운영체제에서도 쓰임
	- 운영체제가 프로세스의 작업 요청을 들어온 순서대로 큐에 넣고 cpu가 순서대로 꺼내서 처리 -> FIFO 스케쥴링
- 헤드를 이용해 첫 번째 위치에 데이터 삽입, 가장 마지막부터 데이터 제거
- 데이터 제거는 가장 뒤 노드부터 해야하는데 가장 뒤의 노드에 접근하기 위해서는 가장 앞 노드부터 순서대로 타고 가야해서 까다로움 -> O(n)의 성능
- 이 성능을 개선하기 위해 tail이라는 변수 필요
- head는 가장 앞에 있는 노드를 가리키고 tail은 가장 뒤에 있는 노드 가리킴
- 이렇게 하면 tail을 이용하여 데이터를 O(1)의 성능으로 제거 가능
- 덧붙여 tail이 가리키던 노드를 삭제한 후 이전 노드를 tail로 바꿔주는 작업도 필요
- 하지만 연결리스트는 다음 방향만 가리키는 단방향 연결리스트라서 이전 노드 참조함에 있어서 어려움 -> head를 이용해 맨 앞의 노드부터 찾는 수 밖에 없음
- 그럼 또 O(n)과 다를 바 없기에 현재 노드가 이전 노드도 가리킬 수 있는 이중연결리스트로 수정(양방향 연결리스트)
- 이중연결리스트로 이전 노드를 참조할 수 있다면 tail변수 하나를 이용해 현재 노드를 제거하고 tail이전 노드를 tail로 새로 할당할 수 있게 됨

- 큐의 추상자료형 
	- 데이터 삽입
		- enqueue
	- 데이터 제거
		- dequeue
	- tail이 가리키고 있는 데이터(가장 먼저 들어간) 제거하지 않고 참조
		- front
	- 큐가 비었는지 확인하는 기능
		- isEmpty

- 큐의 구현을 위해 이전 노드도 가리킬 수 있도록 해야 함

## 해시테이블
- 해시, 맵, 해시맵, 딕셔너리 라고도 불림
- 해시와 테이블이 합쳐진 자료구조
- 테이블이란 표
- 자료를 리스트로 저장하는 경우 인덱스로 배열에 접근하다보니 중간 중간 빈 공간이 생김
- 이 때 한 자리 인덱스로 줄여 데이터를 절약하는 방법이 있는데 그 계산을 하는 것을 해시라고 부름
- 해시함수로 테이블의 인덱스를 새로 만들기 때문에 해시테이블이라고 부름
- key와 value
- key만 알면 value에 O(1)의 성능으로 읽기 가능
- 삽입, 수정 삭제 역시 O(1)의 성능
- 하지만 해시 함수로 인덱스를 새로 만들 때 이미 저장된 값이 있으면 충돌이 발생
- 충돌을 해결하기 위해 해당 인덱스를 연결리스트로 구성해 데이터들을 연결
- 이 방법을 사용하면 기존 값과 새 값 모두 같은 인덱스에 저장 가능 
	- 해시함수를 거쳐 특정 인덱스의 연결리스트 참조 
	- 원하는 값을 찾기 위해 연결리스트의 인덱스들 뒤지기-> O(n)의 성능
- 따라서 데이터를 골고루 분배시켜줄 수 있는 해시 함수 설정이 중요

- 장점
	- 빠른 데이터 읽기, 삽입, 삭제
- 단점
	- 공간의 효율성이 좋지 않음
	- 미리 많은 공간을 마련해둬야하고 해시 함수에 따라 공간의 낭비가 극대화될 수 도 있음
	- 메모리를 많이 차지함

- 해시테이블 추상 자료형
	- 데이터 삽입
		- set
	- 데이터 읽기
		- get
	- 데이터 제거
		- remove

## 버블 정렬

- 버블의 성능 O(n제곱)

### 버블 정렬 구현
- 먼저 BubbleSort라는 함수 생성
- 배열을 받을 매개변수 arr을 만들어줌
- 배열을 순회할 for문 만들어줌
	- 만약 배열의 길이가 4라면 자리교체는 최대 3번을 해야하므로 배열의 길이보다 1작은 횟수만큼 반복시켜 줘야함
- 배열을 순회하는 for문안에 for문을 하나 더 만들어줘야 함
	- 첫 번째 원소부터 정렬이 된 원소의 이전 원소보다 하나 이전의 원소까지 순회해야 함
	- 정렬이 완료된 개수만큼을 i로 빼줘서 범위를 줄여 줌
	- 예를 들어 길이가 4인 배열에서 마지막 원소 하나가 정렬된 상태라면 i값이 1이고 배열의 길이 4에서 i값 1과 거기서 1을 더 빼주니 두 번만 반복될 것임
- 이제 실제로 비교하며 자리 바꿔주기
	- 만약 앞에 데이터가 뒤에 데이터보다 크다면 덮어쓸 데이터는 잃어버리지 않게 다른 변수에 저장해주고 앞에 데이터를 뒤에 데이터로 덮어씀
	- 그리고 뒤에 데이터는 원래 첫 번째 데이터를 담고 있는 temp값으로 덮어씀
	- 이렇게 하면 배열의 두 숫자가 교체됨
- 두 개의 for문을 돌면 정렬이 완료됨
- function BubbleSort(arr){ for (let  i = 0; i < arr.length -1; i++){ for ( let j = 0; j < ( arr.length - i - 1 ); j++ ){ if( arr[j] > arr[j+1] ){ let temp = arr[j]; arr[j] = arr[j +1 ]; arr[j+1] = temp; } } } }

## 선택 정렬
- 이해와 구현이 간단하지만 아쉬운 성능
- 배열의 정렬되지 않은 영역의 첫 번째 원소를 시작으로 마지막 원소까지 비교 후 가장 작은 값을 첫 번째 원소로 가져윰
- 그 다음도 정렬되지 않은 영역의 첫 번째 원소를 시작으로 마지막 원소까지 비교 후 가장 작은 값을 첫 번째 원소로 가져윰
- 성능 O(n제곱)

### 선택정렬구현
- SelectionSort 함수 생성
- 배열을 받을 매개변수 arr만들어줌
- 다음으로 for문을 만드는데 마지막 원소는 자동으로 정렬되기 때문에 배열의 원소가 n개라면 n-1번 반복
- 이제 정렬되지 않은 영역의 첫 번째 원소부터 마지막 원소 중에 최솟값을 가진 인덱스를 저장할 변수를 만들어 줌
	- 배열의 시작으로 0이 아닌 i를 넣어준 이유는 이 반복문을 한 번 진행할 때마다 최솟값이 하나 이상 정렬되기 때문에 정렬된 영역은 반복에서 제외하기 위한 것
- 정렬되지 않은 영역의 첫 번째 원소부터 마지막 원소까지 순회하며 가장 작은 값을 찾기 위한 for문을 만들어줌
	- j의 값을 i의 값보다 1 크게 해줌. i의 값은 이미 minValueIndex에 저장했기 때문
	- 그리고 배열의 마지막 원소까지 반복해줌
	- 정렬되지 않은 영역을 순회하다가 가장 작은 값을 발견하면 minValueIndex에 가장 작은 값의 위치를 저장해줌
	- 현재 인덱스의 값이 지금까지 알려진 가장 작은 값보다 작다면 현재 인덱스를 가장 작은 값의 인덱스로 저장
- 이 for문을 거치게 되면 minValueIndex에는 정렬되지 않은 영역에서 가장 작은 값이 저장되게 됨
	- 이 값을 정렬되지 않은 영역의 첫 번째 원소와 교체해줌
	- 정렬되지 않은 영역의 첫 번째 원소를 임시 변수인 temp에 넣어줌
	- 그리고 첫 번째 원소를 가장 작은 값으로 덮어쓰고 가장 작은 값이 있던 자리에 temp값을 덮어써줌
	- 이렇게 되면 두 데이터가 교체됨
	- 이렇게 for문들을 거치면 모든 원소가 정렬됨
- function SelectionSort(arr){ for(let i = 0; i < arr.length -1; i++ ) { let minValueIndex = i;  for(let j = i+1; j < arr.length; j++ ){ if(arr[j]) < arr[minValueIndex]{ minValueIndex = j; } } let temp = arr[i]; arr[i] = arr[minValueIndex]; arr[minValueIndex] = temp; } }

## 삽입 정렬
- 선택 정렬과 마찬가지로 배열을 두 영역으로 나눠서 진행
- 정렬되지 않은 영역에서 데이터를 하나씩 꺼내서 정렬된 영역 내 적절한 위치에 삽입해서 정렬하는 알고리즘

- 정렬되지 않은 영역의 첫 번째 원소를(삽입할 데이터) 정렬된 영역의 마지막 원소와 비교
- 정렬된 영역의 마지막 원소가 더 크면 오른쪽 인덱스에 덮어씀
- 마지막에 비교한 4위치에 삽입할 데이터를 삽입함
- 데이터가 제대로 삽입되어 정렬됨
- 다음으로 정렬되지 않은 영역의 첫 번째 원소를 정렬된 영역의 가장 뒤에 있는 원소부터 역순으로 비교
- 정렬된 영역의 가장 뒤에 있는 데이터가 삽입할 데이터보다 작으면 따로 덮어쓰지 않음
- 그렇다면 삽입할 데이터가 그 자리에 그대로 있는 것이 정렬되엇다는 뜻임
- 또 다음으로 정렬되지 않은 영역의 첫 번째 원소를 정렬된 영역의 가장 뒤에 있는 원소부터 역순으로 비교
- 정렬된 영역의 원소가 삽입할 데이터보다 크면 오른쪽 인덱스에 덮어씀
- 그리고 삽입할 데이터를 조금 전에 비교한 데이터의 이전 데이터와 비교
- 그 이전 데이터가 더 크면 그 데이터를 오른쪽 인덱스에 덮어씀
- 이 과정을 반복하는데 삽입할 데이터가 비교할 데이터보다 더 크면 따로 덮어쓰지 않고 마지막으로 비교했던 데이터의 다음 인덱스에 덮어씀

- 성능 O(n제곱)
- 이해와 구현이 간단하지만 아쉬운 성능

### 삽입정렬 구현
- 먼저 함수 생성
- 정렬할 배열을 받을 매개변수 arr을 만듦
- 이제 정렬되지 않은 영역의 첫 번째 원소부터 시작해서 마지막 원소까지 순회하기 위한 for문을 넣어줌
	- i가 1부터 시작하는 이유는 0번째 인덱스 즉 첫 번째 원소는 이미 정렬되어 있다고 가정하기 때문
	- i 인덱스에 해당하는 원소는 정렬되지 않은 영역의 첫 번째 데이터 -> 변수에 따로 저장하기
- 이제 두 번째 for문 만들기
	- 정렬된 영역의 맨 뒤부터 첫 번째 원소까지 역순으로 순회하면서 정렬된 원소의 삽입 위치를 찾는 부분
	- 삽입 위치를 기억해주기 위해 j라는 변수를 먼저 선언
	- 정렬된 영역의 마지막 원소는 정렬되지 않은 영역의 첫 번째 원소의 한 칸 앞
	- 정렬되지 않은 영역의 첫 번째 원소는 i이므로 j에는 i - 1로 초기화를 해 정렬된 영역의 맨 뒤로 설정
	- 정렬된 영역의 마지막 인덱스부터 첫 번째 인덱스까지 역순으로 순회
	- 순회하면서 삽입할 원소와 비교해주는 코드 
	- 현재 순회하는 인덱스의 원소가 삽입할 원소보다 크다면 오른쪽 인덱스에 덮어써줌
	- 그렇지 않다면 삽입할 원소보다 작은 원소의 자리를 찾았으니 for문을 나와줌
	- 삽입할 원소보다 작은 원소의 인덱스는 j에 기록되어 있음

- function InsertionSort(arr){ for( let i =1; i < arr.length; i++){ let insertingData = arr[i]; let j; for(j = i - 1; j >=0; j-- ){ if(arr[j] > insertingData ){ arr[j + 1] = arr[j]; }else { break; } } } }

	- 배열의 마지막 인덱스를 나타내는 rightIndex
	- left와 right는 재귀로 호출할 때 필요한 매개변수
	- leftIndex와 rightIndex가 같은 값일 때까지 즉, 배열의 원소가 1개일 때 까지 분할하기 위해 if 문
- 병합 정렬에서 성능을 평가하는 부분은 Merge()함수 내 흩어진 배열을 합치는 부분

- leftIndex, rightIndex 는 재귀로 호출할 때 필요한 매개변수
- leftIndex, rightIndex가 같은 값일 때까지 즉 배열의 원소가 1개일 때까지 분할하기 위해 if문을 넣어줌
- 배열을 분할하기 위해 중간값을 구하기
	- leftIndex와 rightIndex를 더해서 2로 나누고 인덱스는 정수만 사용할 수 있으므로 parseInt()함수로 정수로 변환해줌
- 이제 배열의 왼쪽 영역을 재귀적으로 호출해 정렬해줌
- 그리고 배열의 오른쪽 영역을 재귀적으로 호출해 정렬
- 이 과정이 끝나면 arr는 중간을 기준으로 정렬이 완료되었을 것
- 그럼 이렇게 반반씩 정렬된 배열을 정렬하며 병합하는 함수 필요
	-  함수이름은 Merge
	- 이렇게 Merge함수를 호출해주면서 시작부분인 leftIndex와 중간 지점인 midIndex, 마지막 인덱스인 rightIndex를 전달해주겠음
	- 그럼 Merge 함수만 정의해서 완성해주면 됨
- Merge 함수
	- 배열의 값을 바로 바꾸지 않고 새로운 배열에 값을 정렬하고 기존 배열에 덮어쓰겠음
	- 그러려면 정렬할 배열과 똑같은 크기의 배열이 필요 -> tempArr
	- 우리의 목표는 왼쪽 영역과 오른쪽 영역을 다른 한 배열로 정렬하는 것이 목표
	- 배열의 왼쪽 영역의 첫 원소와 배열의 오른쪽 영역의 첫 원소를 비교하고 더 작은 수를 tempArr에 넣어주는 것
	- 배열의 왼쪽 영역에서 몇 번째까지 비교했는지 기억할 변수를 leftAreaIndex
	- 배열의 오른쪽 영역에서 몇 번째까지 비교했는지 기억할 변수를 rightAreaIndex
	- 그리고 tempArr에 몇 번째 인덱스에 데이터가 삽입될 지 기억하는 변수를 tempArrIndex로 부름
	- leftAreaIndex와 rightAreaIndex를 비교한 후 더 작은 값을 tempArr의 tempArrIndex에 해당하는 인덱스에 넣어줌
	- 그리고 더 작은 값이었던 rightAreaIndex와 tempArrIndex의 값을 1올려줌
	- 이 과정을 반복하다가 한 영역의 인덱스가 옆 영역을 침범하면 침범한 영역이 전부 병합되었음을 의미함
	- 따라서 왼쪽 영역과 오른쪽 영역을 비교하는 작업을 끝내고 병합이 되지 않은 영역의 데이터를 모드 tempArr로 옮겨줌
	- 그럼 tempArr에 모든 데이터가 병합되어있으니 이 배열을 arr로 옮겨줌

## 퀵 정렬
- 분할 정복 알고리즘
- 정렬하기 전 배열에 있는 숫자 중 하나를 피벗으로 설정
- 배열의 시작과 끝을 가리키는 left와 right
- 왼쪽에서 오른쪽으로 이동하는 변수를 leftStartIndex
- 오른쪽에서 왼쪽으로 이동하는 변수를 rightStartIndex
- 가장 먼저 leftStartIndex가 이동, 오른쪽으로 이동하다가 피벗보다 큰 값을 만나면 멈춤
- 다음으로 rightStartIndex가 이동, 왼쪽으로 이동하다가 피벗보다 작은 값을 만나면 멈춤
- leftStartIndex와 rightStartIndex가 멈추면 이 둘의 값을 교환함
- 이 과정을 반복함
- leftStartIndex와 rightStartIndex가 서로의 방향으로 이동하다보면 결국엔 서로 지나치게 됨
- 그러면 더 이상 이동하지 않고 멈춤 -> leftStartIndex는 rightStartIndex의 오른쪽에 있게 됨
- 이 상태에서 피벗과 rightStartIndex의 값을 교환함
- 그러면 교환한 피벗을 기준으로 왼쪽에 있는 값들은 전부 피벗보다 작은 값이고 오른쪽에 있는 값들은 전부 큰 값
- 일단 피벗은 정렬된 값이 됨
- 그럼 정렬이 완료된 값 기준으로 왼쪽도 오른쪽도 같은 방식으로 진행하면 모두 정렬이 완료됨
- 퀵 정렬은 이렇게 한 번 진행될 때마다 피벗이 정렬되고 정렬된 배열을 좌우로 나눠서 같은 방식으로 재귀호출 해 모든 배열을 정렬함

- 퀵 정렬은 피벗을 기준으로 배열을 반으로 나눔
- 데이터가 한 개가 될 때 까지 나눔 -> logn
- 이렇게 나눠진 단계를 배열의 원소 수 n만큼 진행해야하니 n을 곱해서 nlogn
- 이경우는 평균적인 경우를 말하고 최악의 경우 피벗이 중간이 아닌 한 쪽으로 치우친 경우 O(n제곱)의 성능
- 재귀적인 기법으로 구현과 이해가 어려우나 성능이 좋음

## 동적 프로그래밍 - 메모이제이션
- 재귀를 사용하면 함수가 호출되어 콜스택의 영역을 차지하는 단점 외에도 성능에 크게 영향을 미치는 단점들이 있음
- 피보나치 수열 -> 무한으로 이어지는 수열
- 피보나치 수열을 구현하여 계산하면 반복되는 부분이 많아 성능이 좋지 못함
- 이와 같은 하향식 계산에서는 중복된 계산이 성능에 많은 영향을 미치기 때문
- 메모이제이션은 계산 결과를 저장해서 여러 번 계산하지 않아도 되도록 해줌
- 해시테이블의 장점은 대이터의 탐색, 삽입, 삭제가 빠르다는 점
- 해시테이블의 key로 계산하려는 값을, value로 계산 결과를 저장한다면 계산하려는 값의 검색을 아주 빨리 할 수 있을 것

- 메모이제이션은 속도가 빠르나 그 속도를 위해 메모리(공간)을 사용
- 여러 번의 함수 호출로 메모리 공간에 스택을 차지하고 메모이제이션을 위한 해시 테이블 공간까지 차지하기 때문에 메모리를 많이 차지함

## 동적 프로그래밍 - 타뷸레이션

	- 메모이제이션은 재귀를 이용해 문제를 하향식으로 해결
