## 자료구조와 알고리즘
- 자료구조
	- 데이터가 어떤 구조로 저장되고 어떻게 사용되는지 나타냄
	- 가장 단순한 자료구조는 변수
	- 배열도 자료구조
	- 자료구조에 따라 처리 방법이 달라짐
- 알고리즘
	- 어떤 문제를 해결하기 위한 확실한 방법
	- 모호한 방식은 알고리즘이라고 부를 수 없음
	- 자료구조에 따라서 알고리즘이 달라짐

## 시간복잡도
- 더 좋은 알고리즘이란 사용자의 요구에 따라 다름
- 시간복잡도란 특정 알고리즘이 어떤 문제를 해결하는 데 걸리는 시간
- 코드에서 성능에 많은 영향을 주는 부분은 반복문
- 반복문이 여러 번 반복될수록 실행시간이 길어짐
- 빅 오 표기법
	- 입력이 늘어날 때 계산량이 늘어나는 척도를 나타내기 위한 것
	- 계산에 가장 많은 영향을 미치는 항만 표기
	- ex) 3n* n + 100n => O(3n * n)

## 배열
- 모든 프로그래밍 언어에서 기본적으로 제공하는 자료구조
- 일반적인 배열
	- 일반적으로 프로그래밍 언어에서는 배열을 선언할 때 배열의 크기를 알려줌
	- 배열을 선언했다면 운영체제는 메모리에서 그만큼의 숫자가 들어갈 수 있는 연속된 빈 공간을 찾아서 순서대로 할당함
	- 할당하지 않은 부분에는 의미 없는 값이 저장
	- 운영체제는 배열의 시작 주소, 숫자 1이 들어간 주소만 기억
	- 인덱스를 이용해 특정 값에 접근
	- 배열의 인덱스 참조는 길이에 상관없이 한번에 가져오기 때문에 O(1)의 성능
	- 따라서 배열은 읽기/쓰기 즉, 참조에서 좋은 성능
	- 그러나 데이터의 삽입, 삭제의 성능은 좋지 않음
	- 처음 할당한 공간보다 배열의 크기를 넘어서 할당하면 문제 발생
	- 운영체제는 처음에 사용자에게 특정 크기만큼의 메모리 공간을 요청 받았고 연속된 공간을 할당 
	- 배열의 끝에는 중요한 데이터가 있을 수도 있기 때문에 마음대로 확장할 수 도 없음
	- 따라서 처음 공간보다 더 넓은 값의 배열을 다시 찾아서 할당해야 함
	- 심지어 기존 데이터를 새 공간에 다시 복사까지 해야 함
	- 그렇다고 처음부터 큰 공간을 할당하면 메모리 낭비와 배열 내부에서도 공간 낭비 문제
- 자바스크립트 배열
	- 처음부터 배열의 크기를 지정하지 않음
	- 자바스크립트에서 배열은 상황에 따라서 연속적, 대부분은 불연속적으로 메모리 할당
	- 불연속적으로 할당된 메모리는 내부적으로 연결해서 사용자에게는 배열인 것처럼 보임
- 배열의 장점
	- 읽기와 쓰기와 같은 참조에는 좋은 성능을 보임
- 배열의 단점
	- 크기 예측이 힘들기 때문에 메모리 낭비가 발생할 수 있음
	- 데이터의 삽입, 삭제가 비효율적임
	- 단점을 해결하기 위해 저장하려는 데이터들을 메모리 공간에 분산해 할당하고 이들을 연결 -> 노드라는 것을 만들어서 수행
- 노드의 구조
	- 데이터를 담는 변수 하나와 다음 노드를 가르키는 변수 하나 가짐
	- 데이터가 필요하다면 필요한 데이터만큼 노드를 만들어 데이터를 저장하고 다른 노드를 가리켜 연결 -> 연결리스트라고 부름
## 연결리스트 
- 개념
	- 연결리스트는 첫 노드의 주소만 알고 있으면 다른 모든 노드에 접근할 수 있음
	- 연결이라는 특성 때문에 배열과는 다른 장단점
- 장점
	- 연결리스트에서 데이터를 추가한다면 빈 메모리 공간 아무 곳에 데이터를 생성하고 연결만 해주면 되기 때문에 배열에서 초기 크기를 알아야 한다는 단점 적용 x
	- 배열에서는 중간에 데이터를 삽입하면 그 뒤에있는 데이터들은 모두 뒤로 밀려나기 때문에 오버헤드가 많이 들지만 연결리스트는 다음 가리키는 노드만 바꿔주면 되기 때문에 간단
- 단점
	- 배열은 메모리에 연속된 공간에 할당되어 있어서 시작주소만 알면 뒤에 있는 데이터 접근이 쉬움
	- 연결리스트는 데이터들이 전부 떨어져있어서 바로 접근할 수 없음
	- 연결리스트에서 데이터 참조는 O(n)의 성능
- 배열과 연결리스트 비교
	- 배열은 크기 고정 / 연결리스트는 필요할 때마다 노드를 만들기 때문에 동적
	- 배열은 메모리에 연속된 공간에 할당 / 연결리스트는 메모리에서 힙 영역이라는 곳에 런타임에 불연속적인 빈 공간에 할당
	- 배열은 메모리 접근이 굉장히 빠름 / 연결리스트는 데이터 참조를 위해 앞에서부터 해당 노드까지 접근해야해서 느림
	- 배열에서 데이터를 삽입하려면 기존 모든 데이터를 옮겨야해서 O(n)의 성능 / 연결리스트는 삽입하려는 노드까지 노드를 계속 타고 들어가야 하니 마찬가지로 O(n)

- 어떤 프로그램을 만드는데 데이터의 수가 자주 바뀌지 않고 참조가 자주 일어난다면 배열, 데이터의 삽입과 삭제가 자주 일어나 데이터의 수가 자주 바귄다면 연결리스트

- 추상자료형
	- 어떠한 데이터와 그 데이터에 대한 연산을 표기하는 것
	- 기능만 나열, 구체적인 구현 방법은 나오지 않은 것
- 연결리스트의 추상 자료형(자바스크립트에서 구현)
	- 데이터는 정수라고 가정
	- 연결리스트에서 필요한 연산
		- 연결리스트의 모든 원소를 출력하는 기능
			- printAll()
		- 연결리스트의 모든 원소를 제거하는 기능
			- clear()
		- 원하는 인덱스에 데이터를 삽입하는 기능
			- insertAt(index, data);
		- 마지막 데이터 뒤에 데이터를 삽입하는 기능
			- insertLast(data);
		- 원하는 인덱스의 데이터를 제거하는 기능
			- deleteAt(index);
		- 마지막 데이터를 제거하는 기능
			- deleteLast();
		- 원하는 인덱스를 읽는 기능
			- getNodeAt(index);
