## P-NP
- 어떤 문제가 주어졌을 때 그 문제가 쉬운 문제인지 어려운 문제인지 
- 해결이 가능하다고 알려졌는지 아닌지 판단하는 척도
- 결정 문제
	- 어떤 문제가 주어졌을 때 yes/no 로 대답할 수 있는 문제
- 최적화 문제
	- 어떤 상황이 주어지고 거기서 최적의 해를 찾으라는 문제
	- 대부분의 최적화 문제는 결정 문제로 바꿀 수 있음

- P 문제
	- 결정 문제가 주어졌을 때 결정론적 튜링 머신을 사용해 다항 시간 내에 답을 구할 수 있는 문제
	- 결정론적 튜링 머신
		- 현재 상태에서 다음 상태로 이동할 때 다음 상태가 유일하게 결정되는 머신
		- 다음 상태가 유일한 상태로 결정되면서 문제를 해결하기 때문에 문제를 일방향으로 해결함
		- if문과 else문도 if문이나 else문이 수행될 때 다음 상태가 유일하게 결정되기 때문에 결정론적 튜링머신으로 처리 가능
	- 다항 시간
		- 문제가 해결되는 데 걸리는 시간을 다항식으로 표현할 수 있는 것
		- 단순하게 어떤 문제를 다항 시간 내에 즉, 상수시간이나 로그 시간, 다항 시간으로 풀 수 있는 문제가 P문제임
	- 지수 시간은 다항 시간보다 크기 때문에 다항 시간 내에 해결할 수 없음
- 정렬 문제
	- P문제
	- 정렬 문제를 해결하는 데 가장 쉽게 생각할 수 있는 알고리즘은 버블 정렬 알고리즘 -> O(n제곱)

- NP 문제
	- 결정 문제가 주어졌을 때 비결정론적 튜링 머신을 사용해 다항 시간 내에 답을 구할 수 있는 문제
	- 결정론적 튜링 머신으로 다항 시간 내에 답을 구할 수 없는 문제
	- 비결정론적 튜링 머신
		- 현재 상태에서 다음 상태로 이동할 때 다음 상태의 갯수가 유일하지 않은 머신
		- 현실에서 볼 수는 없고 있다고 가정한 것
		- 문제를 해결하는데 2의 n승과 같이 지수에 n이 있게 되면 이를 지수 시간이라고 함
		- 지수시간은 입력이 조금만 커져도 해결하는 시간이 매우 오래 걸리기 때문에 결정론적 튜링 머신으로 해결하기 힘듦
		- 비결정론적 튜링 머신은 어떤 선택지에서 유일한 상태가 아니라 여러 상태가 공존
	- NP 문제는 어떤 힌트가 주어졌을 때 결정론적 튜링 머신으로 '검증'은 가능함

- NP-hard 문제
	- 어떤 NP 문제들이 있을 때 이 모든 NP문제들을 다항 시간 내에 어떤 문제 A로 환원시킬 수 있다면 그 문제 A
	- 예를 들어 NP문제 A,B,C,D가 있는데 모든 NP 문제들이 어떤 문제 (A)가 해결 됐을 때 쉽게 해결될 수 있다면 NP문제들을 A로 환원시킬 수 있다고 말하고 이렇게 환원된 문제 A를 NP-hard 문제라고 함
- NP-complete 문제
	- NP-hard 문제에도 포함되면서 NP문제에도 포함되는 문제
	- NP-complete 문제는 어떻게든 문제를 해결할 수 있다는 것이 판별난 문제
	- 반면에 NP-hard 문제는 해결이 가능한지 가능하지 않은지도 판별이 나지 않은 문제

## 트리와 이진 트리
- 비선형 자료구조
- 트리구조
	- 하나의 노드에서 나무가 가지를 치듯이 내려가는 것
	- 계층구조를 표현하기 좋음
	- 노드
		- 데이터를 표현하는 덩어리
		- 데이터를 담는 가장 작은 단위
	- 간선(Edge)
		- 각 노드를 연결하는 선
		- 엣지로 연결된 노드에서 아래에 있는 노드는 위에 있는 노드의 자식
		- 자식의 관점에서 위에 있는 노드는 부모가 됨
	- 루트 노드
		- 트리에서 최상위에 있는 노드
	- 터미널 노드
		- 자식노드가 없는 노드
		- 터미널 노드를 제외한 노드는 인터널 노드

- 이진 트리
	- 이진 트리는 각각의 노드가 최대 두 개의 자식 노드를 가질 수 있는 트리
- 트리의 레벨과 높이
	- 트리는 자식 노드로 내려갈수록 레벨이 증가함
	- 루트 노드의 레벨은 1
	- 루트노드의 자식 노드는 루트 노드보다 레벨이 1 높음 -> 레벨 2
	- 트리에서 가장 높은 레벨을 높이라고 말함

- 포화 이진트리 VS 완전 이진트리
	- 포화 이진 트리
		- 트리의 최대 레벨에 있는 모든 터미널 노드가 꽉 찬 트리
		- 예를 들어 높이가 3인 트리에서 레벨 3위치의 터미널 노드가 꽉 차있다면 높이 3을 유지하며 새로운 노드를 삽입할 수 없으므로 포화 이진트리
	- 완전 이진 트리
		- 최대 레벨을 제외한 나머지 레벨에는 모두 채워져 있어야하고 최대 레벨의 노드들은 왼쪽부터 채워진 트리
		- 예를 들어 높이가 3일 때 레벨 2까지는 모든 노드가 채워져있고 레벨 3에 해당하는 노드들은 왼쪽부터 채워져있는 경우
## 트리와 이진 트리 - 구현
- 이진 트리의 추상 자료형
	- getData( )
		- 해당 트리(노드)의 데이터 리턴
		- 만약 루트 노드인 1에서 호출한다면 숫자 1 리턴
	- setData( )
		- 해당 트리(노드)의 데이터 설정
	- getLeftSubTree( )
		- 헤당 트리(노드)의 왼쪽 서브 트리 리턴
		- 만약 루트 노드인 1에서 호출한다면 2가 담긴 노드(트리)를 리턴
	- getRightSubTree( )
		- 해당 트리의 오른쪽 서브 트리를 리턴
		- 만약 루트 노드인 1에서 호출한다면 3이 담긴 노드(트리)를 리턴
	- setLeftSubTree( )
		- 해당 트리의 왼쪽 서브트리를 해당 트리로 설정
	- setRightSubTree( )
		- 해당 트리의 오른쪽 서브 트리를 해당 트리로 설정
	- preOrderTraversal( )
		- 해당 트리를 전위 순회하는 기능
	- inOrderTraversal( )
		- 해당 트리를 중위 순회하는 기능
	- postOrderTraversal( )
		- 해당 트리를 후위 순회하는 기능

- 순회
	- 전위 순회
		- 루트 노드 -> 루트의 왼쪽 서브 트리 -> 루트의 오른쪽 서브 트리
	- 중위 순회
		- 루트의 왼쪽 서브 트리 -> 루트 노드 -> 루트의 오른쪽 서브 트리
		- 루트를 중간에 출력했다고 해서 중위 순회
	- 후위 순회
		- 루트의 왼쪽 서브 트리 -> 루트의 오른쪽 서브 트리 -> 루트 노드
		- 루트 노드를 마지막에 출력했다고 해서 후위 순회
- 트리의 전체 구조를 출력하는데 재귀와 순회가 쓰임

	- 특정 노드의 오른쪽 자식 노드는 그 노드의 값보다 항상 큰 값들로만 이뤄짐

## 이진 탐색 트리 - 제거 구현
- 이진 탐색 트리는 단순히 노드만 제거한다고 되는 것이 아님
- 여러 상황으로 나눠서 처리해야 함
	- 터미널 노드 제거
		- 터미널 노드는 자식 노드를 가지고 있지 않기 때문에 단순히 부모 노드와 연결만 끊어주면 간단하게 제거됨
	- 자식 노드가 하나만 있는 노드를 제거하는 경우
		- 제거할 노드와 부모 노드의 연결을 끊고 부모 노드와 제거할 노드의 자식 노드를 연결해줘야 함
	- 자식 노드가 두 개인 노드 제거
		- 자식 노드가 두 개인 노드를 제거하면 왼쪽 자식 트리와 오른족 자식 트리 모두를 잃어버리게 됨
		- 자식 노드 중 어느 하나가 제거한 노드가 있었던 위치에 대신해서 와야함
		- 이 때 이진 탐색 트리의 조건을 무너뜨리지 않는 노드가 와야함
		- 먼저 왼쪽 노드에서 가장 큰 값을 제거한 노드의 위치로 이동시키는 경우
		- 혹은 오른쪽 노드에서 가장 작은 값을 제거한 노드의 위치로 이동시키는 경우
		- 둘 중 어느 것을 선택해도 괜찮음

	- 제거하려는 노드의 왼쪽 노드에서 가장 큰 값을 선택하는 경우
		- 먼저 제거하려는 노드의 왼쪽 자식 노드로 이동
		- 그 후 오른쪽 노드로 계속 가서 가장 큰 값의 노드를 찾음
		- 그렇게 찾은 가장 큰 값의 노드를 처음에 제거하려했던 노드에 덮어써줌
		- 그 후 제거하려던 노드의 왼쪽 자식 노드의 오른쪽 자식 노드를 가장 큰 값의 왼쪽 자식 노드였던 값으로 설정해줌
- 이진 트리는 컴파일러가 사용하는 구문 트리를 만들거나 jpeg, mpeg 파일을 만드는 압축 알고리즘인 허프만 트리를 만들 때 유용하게 쓰임
- 이진 탐색 트리가 잘 구현되지 않으면 O(n)의 성능
	- 예를 들면 이진 탐색트리가 한 방향으로만 연결된 경우 -> 이는 연결리스트와 같은 모습
	- 데이터를 잘 삽입하면 O(logn)의 성능
		- 완전 이진트리나 포화 이진 트리처럼 트리가 균형을 이루고 있어야함
		- 삽입이나 제거할 때 균형을 유지하는 방법들이 있음
		- 이를 자가균형이진탐색트리라고 함
## AVL 트리
- 트리의 균형을 유지하기 위해서는 균형이 맞는지 맞지 않는지 구분할 수 있아야 함
- 왼쪽 자식트리의 높이와 오른쪽 자식 트리의 높이가 최대 1만큼 차이 나도록 허용하고 이보다 더 차이가 난다면 균형이 무너졌다고 판단함
	- 루트 노드를 기준으로 왼쪽 서브트리와 오른쪽 서브트리의 높이 비교
	- 오른쪽 서브트리의 왼쪽 서브트리와 오른쪽 서브트리의 높이 비교
	- 왼쪽도 마찬가지
	- 이렇게 비교하는 과정을 거친 후 높이가 2이상 차이나는 서브트리가 있다면 서브트리의 균형이 맞지 않으므로 전체 트리도 균형이 깨졌다고 봄
- 균형이 맞지 않는 트리의 균형만 맞춰주면 전체 트리의 균형이 맞아짐
	- 트리의 구조에 따라서 오른쪽 또는 왼쪽으로 회전시키고 혹은 두 번 이상 회전시키는 등의 행동으로 균형을 맞출 수 있음
	- 
- 회전의 종류
	- LL 회전
		- 왼쪽 서브트리와 오른쪽 서브트리의 높이 차가 1을 초과하는 경우
		- 즉, 왼쪽 서브트리보다 오른쪽 서브트리의 높이가 더 높을 경우
		- 루트 노드를 왼쪽으로 회전시키면 균형을 맞출 수 있음
	- RR 회전
		- LL회전이 필요한 상황의 반대
		- 오른쪽 서브트리보다 왼쪽 서브트리의 높이가 더 높은 경우
		- 루트 노드를 오른쪽으로 회전시키면 균형을 맞출 수 있음
	- LR 회전
		- 왼쪽으로 먼저 꺾였다가 중간에서 안쪽으로 꺾인 구조
		- 예를들어 왼쪽 서브트리의 높이는 2이고 왼쪽 서브트리의 높이는 0
		- 이런 상황에서 왼쪽 서브트리의 루트를 왼쪽으로 회전
		- 여기서 루트노드를 오른쪽으로 회전
	- RL 회전
		- 오른쪽으로 먼저 꺾였다가 안쪽으로 꺾인 구조
		- 왼쪽 서브트리는 없으므로 높이가 0이고 오른쪽 서브트리의 높이는 2
		- 이런 상황에서 오른쪽 서브트리의 루트 노드를 오른쪽으로 회전
		- 그 후 루트 노드를 왼쪽으로 회전
## AVL 트리 구현하기
- 추상 자료형
	- insert(targetRootNode, data)
	- remove(targetRootNode, data, parentNode = null)

	- 다른 점은 data이외에 node를 가리키는 인자가 추가되었다는 점
	- AVL트리에서 insert와 remove는 재귀함수이기 때문
- AVL 트리에서 이 함수를 구현하기 위한 보조함수들이 필요
	- getHeight(node)

	- getUnBalanceNode(targetRootNode)

	- removeHelper(deletingNode, data, parentNode)

		- this.insert(targetRootNode.getLeftSubTree(), data)를 통해서 자식 노드를 향해 계속해서 함수 다시 호출
		- 맨 위(루트)에서 결정을 내리고 아래로 작업을 위임
	- 상향식 방법
		- this.updateHeight(targetRootNode)
		- 삽입할 때는 위에 말했듯이 null을 만날 때가지 끝가지 내려가서 새 노드를 만드는 하향식 방법을 사용
		- 재귀함수가 종료되면서 부모 노드로 돌아감
		- 부모 노드로 돌아와 높이 업데이트하는 함수 실행
		- 가장 밑에 새로 생긴 노드부터 거꾸로 루트 노드까지 올라오며 상향식으로 높이 계산
- 정리
	- insert함수가 호출되면(데이터를 삽입할 때), 함수는 루트 노드부터 시작하여 null(빈공간)을 찾을 때까지 자기 자신을 계속 호출함
	- if문을 통해서 빈자리를 찾아감
	- 재귀 호출을 반복하다 기저 조건인 targetRootNode === null인 지점에 도달하면, 즉 빈자리를 찾았으면 새로운 노드 객체가 메모리에 생성되고 이 노드가 자신을 호출했던 바로 위 단계(부모 노드)의 함수로 전달됨
	- 함수가 종료되며 위로 복귀(상향식 연결 및 업데이트)

	- null을 만나면 실제 노드 만들고 자기를 호출한 부모에게 자신을 보냄
	- 자식이 보낸 노드를 set을 통해서 왼쪽이든 오른쪽이든 연결
	- 높이 업데이트, 로테이션 하고 반환
	- 그다음 부모에게 전달 이 과정 루트까지 반복


- remove와 removeHelper 함수
	- remove는 재귀적으로 동작
	- 데이터가 현재 노드보다 작으면 왼쪽으로, 크면 오른쪽으로 계속 내려감
	- 데이터가 일치하는 노드를 찾으면 removeHelper에게 제거 명령
	- 그 결과물로 삭제 후 대체된 노드를 받아옴
		- 대체된 노드는 삭제한 노드의 자식 노드
	- 삭제 직후 함수가 종료되면서 다시 부모쪽으로 거슬러 올라감
		- 높이 업데이트
		- 균형 체크
		- 회전
		- 등을 수행하면서 부모로 거슬러 올라감
	- removeHelper 함수
		- 삭제할 노드를 찾은 경우 자식의 상태에 따라 3가지 제거법 수행
		- 1. 자식이 없는 경우(터미널 노드)
			- 단순 삭제 
			- 연결을 끊고 null 반환
		- 2. 자식이 하나인 경우
			- 삭제할 노드가 빠지고 대체할 노드로 삭제할 노드의 자식이 옴
		- 3.자식이 둘 인 경우
			- 자식이 둘인 노드를 지우면 둘 중 어느 값을 대체할 노드로 삼아야할지 정해야 함
			- 보통 왼쪽 서브트리에서 가장 큰 값을 가진 노드를 대체할 노드로 설정
			- 대체할 노드를 삭제할 노드 자리로 복사해옴
## Red - Black 트리
- AVL트리는 Red-Balck트리보다 더 엄격하게 균형을 유지
	- 따라서 트리에 데이터 삽입과 제거 시 더 많은 회전이 발생
	- 따라서 삽입과 제거의 속도가 느림 그러나 검색의 속도는 더 빠름
- red-black트리는 좀 더 느슨하게 균형을 유지
	- 삽입과 제거 시 더 적은 회전을 하기 때문에 성능이 좋음
	- 그러나 검색 시 더 많은 시간이 걸릴 수도 있음
- 삽입과 제거 / 검색 중 어느 기능을 더 빈번하게 사용할지에 따라 어떤 트리를 사용할지 선택

- Red-Black트리의 규칙
	- 모든 노드는 빨간색이나 검은색 두 가지 색 중 하나를 가지고 있음
	- 루트노드는 항상 검은색
	- 모든 터미널 노드는 검은색(NIL 노드)
	- 노드가 자식노드를 가지고 있지 않으면 자식 노드 자리에 NIL노드라는 것을 만들어 넣음
		- 따라서 모든 터미널 노드는 NIL노드가 되고 이는 무조건 검은색
	- 연속해서 빨간색 노드가 올 수 없음
	- 검은색 노드는 연속해서 올 수 있음
	- 루트노드에서 터미널 노드인 NIL 노드까지 모든 경로에는 같은 수의 검은색 노드가 있어야 함
- Red-Black트리의 높이
	- 원래 우리가 알던 트리의 높이 개념
	- 여기에 하나의 높이 개념이 더 있음
	- Black Height
		- 루트노드부터 터미널(NIL)까지 경로에 존재하는 검은색 노드의 수를 말함

- 삽입
	- 이진 탐색 트리처럼 데이터를 삽입하고 균형을 잡아줌
	- 균형을 잡아줄 때 AVL트리처럼 회전도 하지만, 노드의 색깔을 다시 칠하는 Recoloring도 진행
	- red-black트리는 새로운 노드를 삽입할 때 무조건 빨간색으로 칠함
	- rebalance AfterInsertion 함수를 호출해 균형을 잡아줌
- <mark style="background: #FFF3A3A6;">rebalance AfterInsertion 함수가 처리해야하는 것</mark>
	- 새로운 노드가 루트노드인 경우, 즉 트리에 데이터를 처음 삽입하는 경우
		- 새로 삽입한 노드는 무조건 빨간색이니 루트노드가 항상 검은색이라는 규칙을 위반하지 않도록 색을 검은색으로 바꿔줌
	- 부모노드와 삼촌노드가 빨간색인 경우
		- 삼촌노드는 부모노드의 형제노드
		- 이 경우, 부모와 삼촌노드를 검은색으로 할아버지 노드를 빨간색으로 칠함
		- 그러나 만약, 증조할아버지 노드가 빨간색이라면 연속해서 빨간색 노드가 올 수 없다는 규칙을 어기게 되므로 할아버지를 대상으로 규칙을 위반하지 않을 때가지 재귀적으로 올라가면서 색을 바꿔줌
	- 부모노드는 빨간색, 삼촌노드는 검은색, 새로운 노드는 안쪽 손자인 경우
		- 안쪽 손자란 할아버지 노드를 기준으로 부모노드, 새로 삽입된 노드의 모양이 삼각형을 이룬 경우
		- 부모노드가 빨간색이기 때문에 연속해서 빨간색 노드가 올 수 없다는 규칙을 위반
		- 부모노드를 삽입된 노드의 반대쪽으로 예를 들어 새로 삽입된 노드가 부모 노드의 왼쪽에 삽입됐다면, 부모노드를 오른쪽으로 회전
		- 그리고 부모노드가 회전했던 반대방향으로 할아버지 노드 회전
		- 그리고 새로 삽입된 노드를 검은색, 할아버지 노드를 빨간색으로 바꿔줌
	- 부모노드는 빨간색, 삼촌노드는 검은색, 새로운 노드는 바깥쪽 손자인 경우
		- 바깥쪽 손자는 삽입된 노드가 할아버지 노드, 부모노드와 일자로 연결된 모양
		- 먼저 할아버지 노드를 삽입된 노드의 반대방향으로 회전
		- 그리고 부모노드는 검은색으로, 할아버지 노드는 빨간색으로 바꿔줌
- 제거
	- 검은색 노드가 제거될 때 black height가 달라지는 것이 문제가 됨
	- 루트노드에서 터미널 노드인 NIL노드까지 모든 경로에는 같은 수의 검은색 노드가 있어야하기 때문
	- 제거는 3가지 상황으로 나뉨
	- 1. 제거할 노드의 두 개의 자식노드가 모두 NIL노드인 경우
		- 단순히 제거할 노드를 제거해주고 제거할 노드의 부모 노드의 오른쪽 자식노드를 NIL노드로 만들어주면 됨
	- 2. 제거할 노드의 자식 노드 중 한 개가 NIL노드인 경우
		- 해당 노드(제거할 노드)를 제거해주고 제거한 노드의 자식 노드가 제거한 노드를 대체하면 됨
	- 3. 제거할 노드의 자식에서 NIL노드가 한 개도 없는 경우
		- 제거할 노드를 제거해주고 왼쪽 자식 노드에서 가장 큰 값의 노드가 제거할 노드를 대체하면 됨
		- 대체한 노드의 자식으로 제거한 노드의 나머지 자식노드를 설정
	- 제거할 노드가 빨간색이었다면 규칙을 어기지 않음
	- 제거할 노드가 검은색인 경우
		- black height가 깨질 확률이 높음
		- 빨간색 노드가 연속으로 올 확률도 높아짐
- 균형을 잡을 때 처리해야할 경우들(제거할 노드가 검은색이었던 경우)
	- 1. 제거할 노드의 형제 노드가 빨간색인 경우
		- 제거할 노드가 제거
		- 형제 노드의 색을 검은색으로 바꿔줌
		- 부모 노드의 색을 빨간색으로 바꿔줌
		- 루트노드에서 터미널 노드인 NIL노드까지 모든 경로에는 같은 수의 검은색 노드가 있어야한다는 규칙을 지키기 위해 회전 필요
		- 부모 노드 왼쪽에 있던 자식을 제거한 경우 부모노드를 왼쪽으로 회전
		- 새로운 형제노드가 생김
		- 부모 노드를 검은색으로 바꿔주고
		- 새로운 형제 노드를 빨간색으로 바꿔줌
	- 2. 형제노드와 형제 노드의 두 자식노드가 모두 검은색이고 부모노드는 빨간색인 경우
		- 제거할 노드 제거
		- 형제 노드의 색을 빨간색으로 바꿔줌
		- 부모노드의 색을 검은색으로 바꿔줌
	- 3. 형제 노드와 형제 노드의 두 자식노드, 부모노드가 모두 검은색인 경우
		- 제거할 노드 제거
		- 형제 노드의 색을 빨간색으로 바꿔줌
		- 이 경우 부모노드와 할아버지 노드 사이에 다른 노드가 있었다고 가정하고 이 노드를 제거한 경우로 가정함
		- 그렇다면 부모노드가 대체할 노드가 되고 할아버지 노드가 부모노드 , 그 여 노드가 형제노드가 됨
		- 이는 두번째 경우와 같으므로 같은 처리를 해줌
		- 새로운 형제노드를 빨간노드, 새로운 부모노드를 검은색 노드로
	- 4. 형제노드가 검은색이고 형제의 두 자식 노드 중 하나라도 빨간색 노드가 있고 바깥쪽 조카노드가 검은색인 경우
		- 바깥쪽 조카노드
			- 형제노드의 자식 노드 중에서 제거할 노드의 반대쪽에 있는 노드
			- 예를 들어 제거할 노드가 부모노드의 왼쪽에 있으면 바깥쪽 조카노드는 형제 노드의 오른쪽 노드
			- 안쪽 조카노드는 제거할 노드와 같은 쪽 노드
		- 제거할 노드를 제거(자리 기억)
		- 부모 노드의 왼쪽 자식노드는 제거할 노드의 자식 노드가 됐음
		- 여기서 안쪽 조카노드를 검은색으로 형제 노드의 색을 빨간색으로 바꿔줌
		- 형제 노드를 제거한 노드의 반대 방향으로 회전시킴
		- 제거할 노드가 부모 노드의 왼쪽에 있었다면 오른쪽으로 회전
		- 이렇게 되면 제거한 노드의 형제노드가 바뀜
		- 새로운 형제노드의 색을 부모노드의 색으로 바꿈
		- 부모노드와 바깥쪽 조카노드의 색을 검은색으로 바꿈
		- 마지막으로 부모노드를 제거한 노드 방향으로 해줌
	- 5. 형제 노드가 검은색이고 형제의 두 자식 노드 중 하나라도 빨간색 노드가 있고 바깥쪽 조카 노드가 빨간색인 경우
		- 제거할 노드 제거함
		- 형제노드의 색을 부모노드의 색으로 바꿔줌
		- 부모노드와 바깥쪽 조카노드의 색을 검은색으로 바꿔줌
		- 제거된 노드 방향으로 부모 노드 회전

- NIL 노드
	- 이 트리에서 모든 터미널 노드는 NIL노드
	- NIL노드는 모드 검은색
	- 구현할 때 null을 nil노드로 생각할 것
	- 예를 들어 현재 노드의 오른쪽 자식 노드가 null이라면 오른쪽 자식 노드는 nil 노드
	- 그러나 이렇게 null을 nil노드로 취급하긴하지만 실제로 노드로 취급하면 오류가 발생
	- null은 노드 속성에 접근할 수 업기 때문(색깔이나 부모노드, 자식노드 참조불가, 함수 호출 불가)
	- 오류를 방지하기 위해 노드의 속성을 가지는 nilnode 생성
	- 노드의 속성이 필요할 때는 Null 대신 nilnode를 만들어 처리하고 처리가 끝나면 다시 null로 바꿔서 nil노드로 표현
