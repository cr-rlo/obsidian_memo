6. 데이터 모델링의 관계
	1. 관계는 존재에 의한 관계와 행위에 의한 관계로 구분
	2. ERD에서는 관계를 연결할 때 존재와 행위를 구분하지 않고 단일화된 표기법
	3. UML에는 클래스다이어그램의 관계 중 연관관계와 의존관계가 있고 이것은 실선과 점선의 표기법으로 다르게 표현이 됨
	4. 연관 관계는 항상 이용하는 관계로 존재적 관계에 해당하고 의존관계는 상대방 클래스의 행위에 의해 형성되는 관계로 행위적 관계
	5. 연관 관계는 소스코드에서 멤버변수(속성, 명사)로 선언하여 사용할 수 있고 의존관계는 오퍼레이션에서 파라미터(동사) 등으로 이용할 수 있음
7. 배타적 관계
	1. 하나의 엔터티가 여러 자식 엔터티와 동시에 관계를 맺을 수 없다
	2. 하나의 엔터티가 여러 개의 다른 엔터티 중 하나와만 관계를 맺을 수 있다
	3. 두 엔터티가 반드시 1:1 관계
	4. 자식 엔터티가 부모 엔터티 없이 독립적으로 존재 가능함을 의미

	- NOCYCLE 옵션을 사용하면 순환 참조가 발생한 이후의 데이터를 포함하여 출력하지 않는다

- NOT -> AND -> OR 순으로 연산
- SELECT SALE_DATE, AMT,
	 SUM(AMT) OVER (ORDER BY SALE_DATE) AS CUM_AMT
	FROM SALES;
	- 윈도우 함수
	- over 절을 보면 order by 절이 있고 뒤에 아무것도 없기 때문에 dafault 값이 숨겨져있다고 보면됨
	- 디폴트 옵션은 range between unbounded preceding current row
	- 즉, 첫 번째 row 부터 current row(나)까지 => 누적을 의미하는 윈도우가 범위
	- 여기서 앞에 sum이 있기 때문에 누적합이 계산이 됨
	- 즉, 날짜순으로 정렬된 각 행까지의 누적 합계를 계산한다.
	- over 절에는 partion by가 꼭 필요하지는 않다 -> 있다면 그룹화
- IN 과 NOT IN
	- IN은 or으로 변환되기 때문에 null값이 포함되어있어도 큰 상관이 없지만
	- NOT IN은 and로 변환되기 때문에 null값이 하나라도 섞여버리면 공집합 출력
	- EXIST 같은 경우에는 null의 영향 받지 않음

	- SELECT 절에서 결과 집합의 각 행에 순차적으로 부여되는 의사컬럼이다
	- 인덱스 생성 시 자동으로 생성되는 물리적 컬럼이 아님
- 스칼라 서브쿼리
	- 스칼라 서브쿼리는 단일 컬럼 단일 행
	- 집계함수는 결과값을 하나로 출력해주기 때문에 괜찮
	- 그렇지 않으면 에러 발생
- NVL
	- NVL(SAL, 100)
		- sal이 null이면 100 출력
	- NVL2(SAL, 100, SAL)
		- sal이 null이면 SAL
		- null이아니면 100
- JOIN
	- CROSS JOIN은 조인 조건이 없음
	- INNER JOIN은 등가 조인뿐아니라 범위 조건 등등도 가능
	- NATURAL JOIN은 두 테이블에서 이름이 같은 컬럼을 자동으로 찾아 등가조인
	- USING 절은 두 테이블에서 컬럼명이 서로 다른 경우에도 사용할 수 있다
