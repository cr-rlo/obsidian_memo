	- hash join은 조인 칼럼의 인덱스가 존재하지 않을 경우에도 사용할 수 있는 기법

	- 해시테이블을 저장할 때 메모리에 적재할 수 있는 영역의 크기보다 커지면 임시 영역(디스크)에 저장
	- hash join을 수행할 때는 결과 행의 수가 적은 테이블을 선행 테이블로 사용하는 것이 좋음

- 기본 엔티티

	- 상품, 회원, 부서, 고객은 그 자체로 현실에 존재하는 요소이므로 기본 엔티티에 해당한다.
- 중심 엔터티
	- 중심 엔터티는 기본 엔티티에서 파생된 엔터티로 업무 과정 중 하나
	- 예를 들어, 고객이 물건을 구매하기 위해 주문을 한다면, 여기서 고객은 기본 엔터티 이고, 주문은 고객으로 부터 파생한 중심 엔티티가 된다. 
- 행위 엔터티
	- 행위 엔터티는 기본 엔터티와 중심 엔티티에서 파생된 엔터티로 고객이 주문을 하면 그 결과로 주문 내역이 나오는데 여기서 주문 내역이 행위 엔티티 이다.
	- 다른 예로 고객이 이벤트 응모를 한다면 , 고객은 기본 엔티티 이고, 이벤트 응모는 중심 엔티티 이며, 이벤트 응모 이력은 행위 엔티티 이다.

- ROWNUM
	- ROWNUM은 SELECT문에서 행이 <mark style="background: #FFB86CA6;">인출될 때</mark> 행에 부여되는 일련번호
	- 조회되는 순간 위에서부터 1,2,3... 번호를 붙이는 것
	- 테이블에 원래 저장된 번호가 아닌 조회할 때 임시로 붙는 번호
	- 컬럼처럼 보이지만 실제로는 조회 과정에서 만들어지는 값 -> 테이블에 저장된 값이 아님
	- ROWNUM은 SELECT 문이 실행될 때, DB가 결과를 만들면서 행을 하나 결과에 넣으려고 하는 순간(인출될 때) 그 순간 번호를 붙임
	- 즉, ROWNUM = 1은 결과에 아직 아무 것도 없으면 지금 들어가려는 행이 1번이 된다는 뜻
	- 따라서 처음부터 WHERE ROWNUM = 2 하면 통과가 되지 않음 
		- 첫 번째 행은 ROWNUM = 1이라서 1=2 -> 거짓 -> 결과에 안 들어감
		- 그러면 WHERE 절이 거짓이 되니까 결과에 들어간 행의 수는 여전히 0
		- 따라서 다음 행도 ROWNUM = 1
		- 계속 1만 나오고 2는 영원히 나오지 않음
	- 하지만 이 때, ROWNUM을 1,2,3,4로 출력하려면 인라인 뷰를 사용하면 됨
		- ROWNUM은 ORDER BY보다 먼저 붙음
		- SELECT ROWNUM한 후 ORDER BY를 해버리면 정렬되기 전에 이미 번호가 붙어버림 -> 정렬된 결과에 1,2,3,4 붙이기가 안됨
		- 이때, 인라인 뷰 사용
		- 인라인 뷰를 사용하면 정렬한 후 ROWNUM을 붙여서 원하는 결과 도출가능
