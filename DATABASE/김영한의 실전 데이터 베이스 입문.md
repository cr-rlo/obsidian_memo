- 데이터 저장, 추상화, 동시 접근 제어, 직접 접근 금지 등의 기능 수행

## 관계형 데이터베이스
- mysql: 정형화된 데이터 관리, ACID 트랜잭션 보장, 성숙한 기술과 풍부한 생태계
- 가장 널리 사용되는 데이터베이스 시스템
- 테이블 간의 관계를 기반으로 데이터를 구조화

## MySQL
- 가장 널리 사용되는 오픈소스
- 복잡한 분석 쿼리나 대규모 트랜잭션 처리 성능은 다소 부족하다는 평가
- 지속적인 개선 중
- 행: 하나의 행은 개별적인 데이터 항목 하나를 나타냄
- 열: 표에서 세로줄, 어떤 종류의 데이터가 저장될지를 정의
- 각 데이터를 유일하게 만들어주는 식별자, 기본 키(primary key)
	- 고유성, not null 꼭 지킬 것
- 외래키: 한 테이블의 열이 다른 테이블의 기본키 값을 참조하는 것
- 두 테이블이 외래키 값을 통해 관계가 있을 때 한쪽을 부모, 한쪽을 자식이라고 함
- 자식 테이블은 외래키 값을 통해 부모 테이블을 참조

## data type
- INT: 정수를 의미, 소수점이 없는 숫자를 저장할 때 사용 
- VARCHAR(n): 문자열 의미, n은 저장할 수 있는 최대 글자 수, 실제 데이터 길이인 글자만큼의 공간만 차지, 가변 길이
- CHAT(n): 항상 n 글자 길이를 차지하는 고정 길이 문자열, 선언한 길이(n)만큼의 공간을 항상 차지함, 선언된 길이보다 입력된 데이터가 짧으면 나머지를 공백으로 채움
- DATE: 날짜 형식을 저장할 때 사용함, 날짜 정보만 저장
- DATETIME: 날짜에 시간까지 저장, 입력된 값을 그대로 저장
- TIMESTAMP: DATETIME과 유사하게 날짜와 시간을 저장하지만, 데이터를 저장할 때 현재 서버의 타임존을 기준으로 협정 세계시로 변환하여 저장하고 데이터를 조회할 때는 현재 서버의 타임존에 맞춰 다시 변환해서 보여줌
- BLOB: 이미지, 오디오, 비디오 같은 대용량 데이터
- ENUM: 단일 선택 타입, 미리 정의한 값 목록 중 하나만 선택하여 저장할 수 있음
- SET: 다중 선택 타입, 미리 정의한 값 목록 중 여러 개를 동시에 선택하여 저장할 수 있음

## DDL

- 데이터를 실제로 조작하기 위한 명령어

## DCL
- 데이터에 대한 접근 권한을 부여하거나 회수하는 등 데이터의 보안과 관련된 권한

## TCL
- DML로 수행된 데이터 변경 작업들을 하나의 거래 단위로 묶어서 관리
- 은행에서 계좌이체를 하는 과정을 생각해보면 됨
- 인출만 성공하고 시스템이 멈춰버린다면 입금되지않고 작업이 끝나버림
- 이런 사태를 막기 위하여 두 작업을 하나의 덩어리로 묶고 모두 성공해야 최종적으로 저장, 하나라도 실패하면 모든 작업을 되돌림
- COMMIT: 트랜잭션의 모든 작업을 최종적으로 데이터베이스에 확정, 저장
- ROLLBACK: 트랜잭션의 모든 작업을 취소하고 이전 상태로 되돌림

## 제약 조건
- 테이블에 데이터를 저장할 때, 특정 규칙을 지키도록 강제하는 장치
- NOT NULL: 값이 없음을 허용하지 않음, 데이터를 INSERT 할 때 이 열의 값은 반드시 입력되어야 함
- UNIQUE: 중복 불가 항목 지정, 테이블 내에서 항상 고유한 값 입력되어야 함
- PRIMARY KEY: PK 테이블 당 하나만 존재할 수 있음, 모든 행을 유일하게 식별, 중복불가와 값없음 불가 특성 모두 가짐, 모든 테이블에는 반드시 존재해야 함
	- AUTO_INCREMENT: pk에 자주사용하는 옵션, 정수 타입의 pk에 이 옵션을 설정하면 새로운 데이터가 추가될 때마다 1씩 자동으로 증가하는 번호를 할당해 줌
- FOREIGN KEY: FK 한 테이블을 다른 테이블과 연결하는 관계의 고리, 참조하는 열의 값은 반드시 참조되는 테이블의 PK값중 하나여야 한다는 참조 무결성 강제
	- 주문테이블에 fk값이 99가 입력된다고 가정하면 고객 테이블에는 그 고객번호가 없다 그럼 오류가 발생함
	- 
- DEFAULT: 데이터를 INSERT 할 때 특정 열의 값을 명시하지 않으면, 설정된 기본값이 입력됨, 예를 들어 회원 가입 시 포인트를 따로 주지않으면 0으로 자동설정
- CHECK: 컬럼에 입력되는 값이 특정 조건을 만족하는지 검사, 조건에 맞지 않는 데이터의 입력을 막음

## WHERE - 기본 검색
- 특정 조건을 만족하는 데이터를 집어서 조회할 때
- SELECT 열이름 FROM 테이블이름 WHERE 조건;
- 조건문은 보통 비교 연산자를 사용해 만들어짐
	- = : 같다, 문자열 전체가 정확히 일치해야 조회
		- WHERE 조건 LIKE '유사값%': 유사한 값으로 시작하는 모든 값도 조회
		- NOT LIKE 도 있음
	- != 또는 <> : 같지않다
	- > :크다
	- < : 작다
	- >= : 크거나 같다
	- <= : 작거나 같다
- 논리연산자로 여러 조건 조회
	- AND: 양쪽의 조건이 모두 참일 때 최종적으로 참
	- OR: 양쪽의 조건 중 하나라도 참이면 최종적으로 참
	- NOT: 주어진 조건을 부정, '아닌'의 의미
	- BETWEEN a AND b: a와 b사이의 값, a에는 최솟값 b에는 최댓값
	- NOT BETWEEN a AND b: a와 b사이의 값을 제외하고 조회, a에는 최솟값 b에는 최댓값
	- WHERE 조건 IN(목록): 괄호 안에 있는 목록 중 하나라도 일치하는 것이 있으면 선택 조회 
	- NOT IN 도 있음
- 와일드 카드 문자
	- %: 0개 이상의 모든 문자
	- _ : 한 개의 문자

## LIMIT - 개수제한
- 조회 결과 개수를 제한
- ORDER BY 뒤에 위치하며, 조회할 결과의 최대 개수 제한
- SELECT 열이름 FROM 테이블이름 WHERE 조건 ORDER BY 정렬기준 LIMIT 개수; 
- SELECT * FROM products ORDER BY price DESC LIMIT 2; : 내림차순으로 정렬
## 특정 범위의 결과만 조회 - LIMIT, OFFSET
- offset: 앞에서부터 몇 개의 데이터를 건너뛸 것인지 지정
- row_count: 건너뛴 다음부터 몇 개의 데이터를 가져올 것인지 지정
- LIMIT 건너뛸개수(offset), 가져올개수(row_count);

## offset을 계산하는 간단한 공식
- offset = (페이지 번호 - 1) * 페이지당 게시물 수
	EX) product 목록을 한 페이지 당 2개씩 보여줄 때, 1 페이지 조회하기는 offset = (1 - 1) * 2 = 0. LIMIT은 0,2 가 된다

## NULL
- 데이터 베이스에서 '값이 없음'을 나타내는 특별한 상태
- 숫자 0이나 빈 문자열과는 완전히 다른 개념. 말그대로 알 수 없는 값
- NULL은 특정 값이 아니기 때문에 등호(=)로 비교할 수 없음
- 따라서 IS NULL 또는 IS NOT NULL의 특별한 키워드 사용
	- IS NULL: 해당 열의 값이 NULL인 행을 찾음
	- IS NOT NULL: 해당 열의 값이 NULL이 아닌, 데이터가 입력된 행을 찾음
- NULL을 가장 작은 값으로 취급

- 내림차순으로 정렬하되 NULL을 가장 위에 두고 싶으면?
  SELECT * FROM products ORDER BY description DESC; 을 하면 NULL이 가장 아래
  -> SELECT product_id, name, description, description IS NULL FROM products ORDER BY description DESC; 을 하면 description IS NULL이라는 열이 새로 생기고 그 값이 0과 1중 하나로 도출됨. NULL인 값이 1로
  -> SELECT product_id, name, description, description IS NULL FROM products ORDER BY description IS NULL DESC, description DESC; 하면 됨

		category,       -- group by에 사용된 컬럼
    COUNT( * )           -- 집계함수
	FROM order_stat
	GROUP BY 
		category;
- SELECT 
		category,
    COUNT( * ) 
	FROM order_stat
	GROUP BY 
		category
	ORDER BY count( * ) desc;
	
## GROUP BY - **주의사항**

- `GROUP BY` 를 사용할 때 `SELECT` 절에는 `GROUP BY` 에 사용된 컬럼과 집계 함수만 사용할 수 있음
- 그룹을 대표하는 값(`GROUP BY` 컬럼)이나, 그룹 전체를 요약한 값(집계 함수)만 조회할 수 있도록 규칙을 정한 것
- 따라서 '전자기기' 그룹에서는 그룹을 대표하는 `category` 인 '전자기기'와, 그룹 전체를 요약한 `COUNT(*)`,`SUM(price * quantity)` 등과 같은 값만 함께 조회할 수 있음
- 그룹 전체를 대표할 수 없는 개별 행의 정보(`product_name` , `order_id` , `customer_name` 등)는 `SELECT` 절에 단독으로 올 수 없음! 
- 그러나 min이나 max로 대표값을 지정해주면 가능

## HAVING - 그룹 필터링
- where은 그룹화가 이루어지기 전, 즉 테이블의 개별 행 하나하나에 대한 조건 검사
- 집계함수는 그룹화 후 계산되는 것
- 따라서 그룹으로 묶은 결과에 대하여 다시 필터링을 하고 싶으면 HAVING사용
- 즉, WHERE은 그룹화 이전에 개개인을 걸러내는 조건이고 HAVING은 그룹화 이후 그룹 자체를 걸러내는 조건
- having절의 조건문에는 집계함수 사용 가능


- SELECT 
	category,
	count( * ) as premium_order_count
from order_stat
WHERE price >= 100000  1. 전체 중 만족하는 것만 다음 단계로
GROUP BY 
	category                     2. 다음 단계로 넘어온 것이 그룹화
HAVING 
	 count( * ) >= 2;          3. 그룹화된 것들 중 조건을 만족하는 그룹을 조회


## SQL 실행 순서
- 우리가 코드를 작성하는 순서는 보통 select -> from -> where -> group by 등 이지만, 데이터베이스는 다음의 논리적 순서에 따라 쿼리를 해석하고 실행한다
- 1. from: 어떤 테이블에서 데이터를 가져올 것인지
- 2. where: 가져온 테이블의 개별 행을 필터링. 그룹으로 묶이기 전의 데이터
- 3. group by: where의 필터링을 통과한 행들을 기준으로 그룹 형성
- 4. having: 만들어진 그룹들을 조건에 따라 필터링
- 5. select: 집계함수 계산, 별칭 부여 등 실행
- 6. order by: 선택된 최종 결과들을 지정된 순서로 정렬
- 7. limit: 정렬된 결과 중에서 최종적으로 사용자에게 반활할 행의 개수 제한

SELECT 
    customer_name,
    count( * ) as `주문 횟수`,
    SUM(price * quantity) as `총 사용 금액`
from order_stat
WHERE category != '도서' OR category IS NULL
GROUP BY 
	customer_name
HAVING `주문 횟수` >= 2
ORDER BY `총 사용 금액`desc;
